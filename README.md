# 烽火山河 · 浏览器玩法原型

原创的二战中国战场单人 FPS 原型。当前仅有一张台儿庄主题地图，已将纯色灰盒场景升级为扫描 PBR 材质、天空环境光与细化建筑，但人物、载具和动画仍为程序化原型，**不是历史地形复原，也不代表《Enlisted》级别的成品品质**。未使用或复制视频、其他游戏的地图、模型、音效或代码；未实现视频中的具体关卡。

## 启动

需要 Node.js 20.19+ 或 22.12+。

```powershell
npm.cmd install
npm.cmd run dev -- --port 5173
```

在支持 WebGL、硬件加速的桌面浏览器访问终端显示的本机地址。依赖安装后无需运行时访问外部美术、字体或 CDN 服务；扫描贴图及天空已随项目保存在 `public\assets`，首次打开需从本地加载约9.1 MiB的美术数据。当前只监听本机；尚未部署公共网站。

`references` 为离线对照资料，不参与Vite热更新监听，避免Windows下收集/查看参考图片时的文件锁导致预览进程退出；游戏源代码仍正常热更新。

## Cloudflare 部署

项目使用 Cloudflare Workers 静态资源托管。根目录的 `wrangler.toml` 明确指定上传 `dist`，无需 Worker 入口代码或 `@cloudflare/vite-plugin`，也不改变本地 Vite 启动和预览方式。只发布构建产物，不上传 `src`、测试或 `references`；`public\assets` 会由 Vite 复制到 `dist\assets`。

在 Cloudflare 的 Workers Git 集成中连接本仓库，根目录使用仓库根目录，并配置：

| 设置 | 值 |
| --- | --- |
| 构建命令 | `npm run build` |
| 部署命令 | `npx wrangler deploy` |
| Worker 名称 | `1931-1945`，与 `wrangler.toml` 一致 |
| 生产分支 | `main` |

确保 Cloudflare 构建的分支已包含 `wrangler.toml`。如果使用其他 Worker 名称，同时修改该配置中的 `name`。不要在构建时自动接入 Vite 插件：缺少明确的 Wrangler 配置时，自动接入可能因现有 Vite 配置没有 `plugins` 数组而失败。

也可以在本机完成 Cloudflare 登录后发布：

```powershell
npm.cmd ci
npm.cmd run build
npx.cmd wrangler login
npx.cmd wrangler deploy
```

仅检查打包和部署配置、不上传资源时，使用 `npx.cmd wrangler deploy --dry-run`（先运行构建）。部署在域名根目录，以保持 `/assets/...` 路径有效；未配置 SPA 回退，缺失资源返回404。发布后仍是桌面 WebGL 单人游戏，不会新增后端、多人联机或跨刷新存档。

## 已实现

- 仅中国阵营可玩；日军守兵 AI；友军跟随、推进、射击。
- 两个可选步兵班身份，每次出击10人，含工兵；Y接管本班存活成员，保留生命、体力、弹药及装填。另有九个自主友军单位和十个敌军单位；迫击炮组仍为三人支援原型，坦克三人车组，飞机单人。
- 开局直接选择步兵、坦克、迫击炮、飞机；无解锁、装备和兵种养成。
- 战斗中只能切换本小队存活队员；当前队员阵亡后自动接管存活队员，整队阵亡才可更换小队。刚阵亡的班组不可立即再选，但可选择另一支同兵种小队。暂停不能换队或刷新生命。
- 整队阵亡后先选择其他小队、重生点，再确认部署；选择期间战场与计时继续，不自动复活。敌我步兵均从登记的重生点入场，新增敌军不再直接刷在当前据点附近。
- 工兵可建造可被枪炮摧毁的集结点，地面小队可在后续出击时选择；附近有敌军时暂不可用。敌方工兵也会前往指定侧翼阵位建造集结点，敌军增援优先从可用的前线点进入。
- 顺序夺取 A / B / C，据点无敌军争夺时持续占领 12 秒；10 分钟时限；胜负、阵亡重部署、暂停。
- 建筑碰撞、射线遮挡、栓动射击与装填、范围爆炸、迫击炮弧线弹道、简化飞行与碰撞。
- 重新部署保留本局据点、计时与击倒统计；返回大厅后开始新一局则重置。刷新页面不保留战局。
- 负重移动原型：步兵慢走/慢跑/冲刺、起停惯性、按实际位移驱动的镜头与枪身步态、地面脚步和落地反馈；冲刺耗体力，换人不补满原队员体力。迫击炮搬运更慢、更耗体力，载具速度不变。

### 负重移动：当前调试规则

这些是本项目的米制调试值，不是《Enlisted》实测参数。WASD默认慢跑，按住C慢走；站立向前移动时Shift冲刺，举枪时Shift仍为屏息。步兵速度为慢走1.75、慢跑3.15、冲刺4.8米/秒；迫击炮搬运分别为1.4、2.45、3.7米/秒。倒退更慢，蹲、卧、举枪另有速度限制。

移动有加速、制动与转向惯性。脚步、镜头和枪身基于碰撞后的实际位移驱动；顶墙不持续踏步，松键后有短暂制动。步频约为慢走2.3、慢跑3、冲刺3.6次触地/秒。枪身随步态、转向和冲刺产生滞后；冲刺后举枪需要约0.45秒恢复，其间不能立即开火。

冲刺持续消耗体力，耗尽后暂时不能冲刺，恢复到35%才解除疲劳限制。每个队员独立保留体力；非控制队员缓慢恢复，Y来回切换不会补满原队员体力。跳跃也需体力。声音当前为按石板/泥地切换的合成接触声，不是正式拟音；角色与手臂仍无完整骨骼步态。

B在标准/减弱/关闭镜头步态之间切换，暂停菜单也可选择；只减弱镜头步态，不取消必要的瞄准、后坐力与枪械动作，也不改变速度或体力。此设置在当前页面内保留，刷新后恢复默认。

`npm.cmd run test:movement` 使用真实键鼠输入检查移动、体力、冲刺转瞄准、顶墙与舒适度开关，另用确定性的20米/50米空场模拟验证30/60/144FPS一致性。设置 `ARTIFACT_DIR` 时额外保存1440×900实机录像与测量JSON；录像需要Playwright的FFmpeg组件（缺失时按其错误提示安装），不设置该变量则无需录像编码器。技术结果不代表F2手感已通过用户复验，进度见 `TODO.md`。

### 第一人称步枪：当前实现与限制

本轮原创样枪采用中正式/Type 24风格，以帝国战争博物馆[1936年巩县藏品 FIR 7135](https://www.iwm.org.uk/collections/item/object/30029566)记载的全长111厘米、枪管59厘米作为比例参照；[1944年藏品 FIR 8276](https://www.iwm.org.uk/collections/item/object/30032572)记载110/60厘米，不能把不同藏品数值混为一件实物。馆藏文字确认其与Mauser Standard Modell的关系，但页面没有可公开查看的实物图像；**尚未完成外观逐项实物对照，也没有确认当前台儿庄小队的具体配枪**。因此界面标为“比例样枪”，不是精确历史资产。

第一人称与己方第三人称使用相同的枪体/枪栓几何与材质；第一人称另外添加手部及动作层，第三人称仍是简化持枪姿势。新模型有连续变化截面的木托、倒角机匣、开口机匣/枪栓、枪管箍、V形照门、准星、护圈与背带，以及原创生成的胡桃木纹、发蓝钢材、布料表面。静态部分按材质合批并共享缓存。肩—肘—腕使用两段程序化求解，上臂约35厘米、前臂约34厘米，袖子有肘部、收口和体积，不再用一根过长直筒连到枪上。手指仍简化，**不是完成的蒙皮人物、专业烘焙资产或生产级LOD管线**，整体观感仍待复验。

射击后有0.65秒开锁、后拉、复进与闭锁动作；未闭锁不能再次发射。R可在拉栓时排队装填，随后执行2.7秒装填；弹仓空时展示五发桥夹，部分弹仓展示逐发补充。弹药仅在动作结束后一次性提交，尚非逐发中断/膛内弹完整模拟。暂停冻结动作；Y切人或1/2切换工兵工具会暂存进度，回到原人/步枪后续接，不在后台补弹。配有同步合成机械声、短时枪口焰与抛壳表现，仍需正式声音和角色动画制作。

举枪用模型照门缺口与准星尖端对齐视线，射击从实际枪口向瞄准目标求交；近距离遮挡以枪口射线为准，不能只凭摄像机可见就穿墙命中。靠墙会回收、放低枪械并退出瞄具，受阻时明确提示且不能发射；移开后恢复。当前为即时射线枪械，没有重力、弹道下坠、风偏或历史归零模拟。

`npm.cmd run test:rifle` 通过真实键鼠检查实际模型长度、照门/准星投影、可见枪栓、枪口射线、补充/空仓装填、暂停/换人/工具打断及贴墙收枪和禁射；设置 `ARTIFACT_DIR` 保存1920×1080实机截图。功能与几何核查不替代F1视觉、握持与手感验收。

## 场景美术迭代

- 砖墙、老化浅色抹灰、灰瓦、石板、泥地和木材使用1K扫描材质，包含颜色、OpenGL法线与打包的AO/粗糙度/金属度贴图；UV按世界米数铺设，避免把一张砖墙图拉伸覆盖整栋房屋。
- 天空使用摄影HDR，结合环境反射、定向日光、4096阴影、ACES色调映射及距离雾，不再使用统一黄绿色背景与纯色表面。
- 缩短主街两侧建筑间距；增加面向街道的商铺招牌、门板、格窗、窗台、雨棚、山墙木构、曲面屋檐与筒瓦檐口。战损建筑采用残墙和焦木轮廓，不再只是移除屋顶的完整方盒。
- 运河增加石砌压顶和桥柱，保留原有桥梁通路；街边增加圆形沙袋、木箱、箍桶、手推车、断瓦、焦痕与弧垂电线。树冠使用带透明裁切的叶片，烟柱使用软边精灵，去除明显的多面体烟球。
- 第一人称步枪采用独立的比例样枪与动作状态，详见上节；士兵改用圆滑体块与装具。人物、第三人称枪械仍是简化模型，不是经过部队装备考据的高模资产或完整骨骼动画。
- 场景按材质合批，士兵躯干按阵营缓存合批；首批11栋底层商铺有真实门窗开口和室内，外围旧封闭建筑仍为背景。未实现建筑破坏或真实弹孔系统。

### 静态表面尺度与木纹方向

`src\surface-uv.js` 在场景合批前生成UV：石板/墙体使用连续世界米制投影，山墙与墙体砖纹共用2.4米重复尺度；主路石板3米、石构件2.5米保持原配置。曲面屋顶按分段坡面实际长度和建筑进深铺设2.5米重复，不再重复计算两倍跨度。上述数值是原型调试值，不是历史或参考游戏的测量结果。

静态木构使用2米重复，扫描图的V方向沿构件局部长轴，随梁、长凳、窗框及地板旋转；圆柱侧面按周长展开。颜色、法线与ARM共用同一UV，不复制贴图或增加材质批次，也不改场景顶点、碰撞和控制。动态门板、专用木端纹及曲轮仍待单独处理；`test\surface-uv.test.js` 覆盖静态尺度、接缝、方向和几何不变约束。

### 首批可进入街区与掩体AI

`src\town-layout.js` 提供固定布局：11栋底层商铺各有前后出口和隔间，南街西侧院落连接作坊并有南北出口。主街墙体表面净距8.76米，墙中心线间距9米；北街对接运河石桥。该尺度是玩法调试布局，不是历史复原。南侧步兵/装甲出发点对准主街，坦克仍不能进入狭窄门洞。室内有木地板、货架、柜台和长凳，但陈设、照明与建筑变化还很初步；没有楼梯、二层活动或动态建筑破坏。

墙体、窗台、门楣、家具与开口对应实际射线/碰撞数据；步兵底层导航改用0.75米A*和胶囊净空检查，不再用4米网格跨过窄门。木地板使用独立地面类别，声音仍是合成原型，F11待解决。

`src\tactics.js` 为班组提供分路接近、掩体占用、进掩体、交替探身及失去目标后的搜索。位置必须有实际遮挡、可用射界和路线才可选；视觉/声音只保留短时位置记忆，射击再次检查视线、枪口和队友阻挡。避让使用有限位移，窄处允许等待。未采用缩放整个人物的假蹲姿；现阶段以立姿可用掩体为主，完整骨骼蹲卧、低掩体、可靠人群避障与反坦克武器选择仍未完成。不能据此声称已完成F3/F8或真人级战术。

`npm.cmd run test:street` 使用真实键鼠走房间、隔间、后门、院落与返回路线，并检查实际3D开口遮挡与友军入室；`npm.cmd run test:tactics` 在正常交战中观察多个敌军实际占用并到达掩体、探身，以及整体身高比例稳定。可用 `ARTIFACT_DIR` 保存实机图像和状态记录；技术结果不替代用户验收。

### 桥面支撑与趴伏视角

`src\ground.js` 为当前固定桥梁提供统一支撑高度：桥面高0.45米，两端各有4米连续坡道，渲染几何、人物/坦克落脚和视角使用同一数据。桥上趴伏眼高为桥面以上约0.45米，不再把眼睛放进桥面或水面；站/蹲/卧、跳跃落地、Y接管、AI枪口和目标高度均使用相应世界高度。`npm.cmd run test:bridge` 要求开发服务器，使用明确标注的 `benchmark=bridge` 几何场景，从桥南登记点以正常键鼠双向走过坡道/桥面，核对实际3D射线表面、趴伏近裁剪、跳跃与换人，可保存实机截图。该场景没有敌军，不作为交火性能证据；正式200人交火由独立基准/人口检查覆盖，不改变正式伤害/出生点来保证测试角色活着。尚非任意坡地、楼层或动态坍塌的完整地面支撑系统。

### 实体门与F交互

首批11栋商铺的前/后门、隔间和两扇院门共35扇实体门，部分初始关闭。步兵接近并看向门口，提示出现后按F开关；门朝远离操作方的一侧打开，不瞬间消失。转动门板使用旋转碰撞，射击和视线检查实际门板；门后有人时停止，移开后继续，不通过推人或穿模完成开门。门轴提示为独立合成声音，正式拟音与整体混音仍待F11。

AI可规划通过门口，但必须实际开门并等待通过；已开启门板的占地会局部刷新到导航，避免每次开门重建全图。F/X交互在鼠标刚移动时使用最新朝向，而不是上一帧摄像机。`npm.cmd run test:doors` 检查F提示、闭门弹着、暂停、通过、受阻、内外侧开启、重开复位及通过窗户命令AI进入关闭房间的实际行为。

G1另补充了接近全开角度仍受阻时的AI主动让门：仅沿安全路径有限移动，不把人传送出去或让门板穿人。0.75米A*网格边的胶囊净空预计算并在门状态更新时局部失效，查询时复用堆、减少路径平滑重复检查；仍保留薄墙、门角和每个实际路径段的净空约束。

门板损毁、锁门/堵塞和高密度堵门仍未完成；外围旧封闭建筑没有全部改造。F采用情境优先级：车内执行地面离车，地面看向门时开关门，无门目标时可返回附近原车；同次按键只执行一个动作。飞机离机仍明确提示未实现，不能把基础坦克下车算作F10全部完成。

### G2实体归属、地面上下车与阵亡过渡

`src\entities.js`为单位、士兵、武器、载具和座位提供稳定ID。士兵持有位置/朝向、生命和个人步枪，坦克/飞机持有自身位置/车体状态、座位和主武器；当前控制器只选择所属单位和士兵ID。原`unit`接口是派生兼容视图，场景模型跟随模拟位置，不再用模型位置作为地面士兵/载具的唯一状态。不是全量ECS或完整渲染/模拟分离，角色局部动画、部分弹道/表现和UI仍有后续工作。

坦克中按F可从安全出口下车，原车不消失，原士兵恢复独立步枪；近距离看向原车再按F返回空席。检查墙、车体、其他车辆及人员，全部受阻则不改变座位/位置。当前只允许原车组返回原车，未实现接管其他单位车辆、全车组撤离指令、空中离机/跳伞、装甲车和野战炮席位。完好遗留车继续计入载具上限，不能反复下车刷车。

Y选择本车组存活成员，可以从地面成员接管仍在车内的成员，反之亦然；个人步枪和车载主炮各自保留弹药/动作，车体生命不刷新、尚未结束的武器冷却不会被缩短。车长/炮手可用现有主炮，驾驶员禁止发炮；2.7/1.9/1.3米眼高仅为三席控制验证原型，不是正式观察窗/炮瞄和历史座舱。Space机枪、专职机枪手、AP/HE和完整驾驶权限/视野仍待F12/F26，不能把本轮称为完整坦克模拟。

`src\control-transition.js`在确认阵亡后进入独立`transferring`状态，显示暗红/阵亡提示，约0.6秒在全暗遮罩下重新选择本单位存活成员，约0.9秒恢复操作；均为本项目调试值。过渡清理输入，Y和长按射击不能提前操作新成员，战场/AI/载具/炮弹继续；Esc暂停冻结时钟，重开/回大厅清理，不采用跨局定时回调。接管后不补血、补弹或继承旧死亡红边；关闭红色效果不改变接管时间。无存活成员进入原覆灭部署。倒地救援、完整死亡动作和所有连续伤亡边界仍需专项验收。

`npm.cmd run test:control`要求开发服务器，使用显式 `?benchmark=control&seed=1938` 小样例（两组自主友军、一辆坦克三人及敌军），以普通输入验证身份/资源、上下车、驾驶员主炮限制及真实自方炮弹爆炸触发的死亡—暂停—接管链路，不使用伤害/传送/无敌接口。设置`ARTIFACT_DIR`可保存实际操作JSON和截图。发布版忽略诊断参数，默认仍为100对100。

控制诊断的坦克登记点位于`(10, 83)`，用现有东侧商铺真实遮蔽下车出口，避免长操作流程依赖暴露成员偶然幸存；敌军人数、伤害、正常AI和自主友军保留。它不是交火性能或敌军无法伤害下车人员的证据，正式重生点未改变。

当前控制链另由 `src\control-input.js` 绑定单位/士兵/载具/席位/武器ID和版本，离散命令同步执行，不额外等待一帧；旧版本或重复命令明确拒绝。Y/F改变控制对象、死亡、暂停和重开会清空按住的移动/鼠标/命令计时，**换人后需重新按下移动、举枪或开火**，避免原成员的持续输入误操作下一成员。车组下车后的个人守位使用安全出口本身，不重复叠班组偏移进入车体。

蹲卧选择与个人观察俯仰现在属于各士兵，通过 `createControlPoseView()`读取；Y使用新成员自己的选择，返回原成员恢复其原值，不再把上一人的低头/趴伏直接带给下一人。相机接管即取对应眼高，继续使用当前桥面/坡面支撑。地面观察俯仰与原车炮塔的原型瞄准角分开，上车不会把步枪的低头角覆盖给主炮，Y/F/阵亡接管均读取原车状态；飞机俯仰/航向属于飞机实体，保留既有限幅。成功入座仍按原规则结束个人蹲卧，离车为站姿；失败入座不改原姿态。刷新视角不再写回这些角度或姿态。

这只完成控制状态归属，并非士兵骨骼蹲卧/命中区、正式炮管俯仰或四岗位独立观察装置；车长/炮手仍共用原型主炮瞄准，F12/F14继续保留。跳跃、后坐力和镜头缓动仍按原规则在交接时清理。`test:bridge`覆盖站/蹲/卧跨成员恢复及桥面眼高，可用`ARTIFACT_DIR`保存实际状态记录；`test:control`同时检查地面观察角不污染原车瞄准角和死亡接管。

驾驶员观察已独立存于原车驾驶席，相对车体转向跟随；鼠标观察不会再转动炮塔或改变主炮俯仰。驾驶员不能用左键发炮或用R启动主炮装填，右键不进入炮手放大瞄准，隐藏主炮准星/第一人称炮口模型并显示岗位限制。Y返回该席恢复其观察，车长/炮手仍读取原炮塔状态；F换席不清空这些状态，WASD驾驶规则未改。当前驾驶观察仍没有正式观察窗、设备位置/遮挡及机械限位，不能视为已还原参考图。

武器视图可见性按控制阶段及席位统一判断：阵亡移交期间新成员的武器也保持隐藏，到可操作时才显示；若连续伤亡后只剩驾驶员，接管完成也不会误显示主炮。`test:control`以实际两次近距炮击覆盖车长、炮手相继阵亡与驾驶员接管，以及驾驶观察/转向/装填限制，不使用伤害或传送写接口。

`src\control-events.js`将换人、上下车、死亡阶段、装填提示、工具视图及本地脚步/门声反馈经有限、一次性事件交给表现层，不在下一局回放旧事件；命令轨迹32条、反馈历史64条，窗口仅公开只读快照，不提供重放/伤害写接口。语音和部分建造UI仍有后续工作，不宣称已整体重构。`test:control`同时检查按住左键/W再Y切到车内时，坦克不自动行驶或空炮装填，原士兵和主炮资源不刷新。

实际移动/落地先记录士兵/单位ID、位置、地表、速度、姿态及落地标志，播放脚步只读该快照，不借用后来切换的队员姿态/地表；已失去控制或入座的旧脚步不在新视角播放。门的真实开/关请求记录门ID、位置和请求方向，不伪称是当前玩家开的门；F仍在接受输入时消费反馈，AI请求在同一模拟帧消费，门动画、堵塞、碰撞和导航不等待音效。暂停不重播，重开清空历史，不记录门/角色模型引用。

`test:movement`、`test:bridge`、`test:doors`覆盖正常步态/地表、桥面落地、F即时请求、AI开门和暂停/重置；`ARTIFACT_DIR`可保存脚步快照与玩家/AI门请求记录。本项沿用原合成音源、频率/音量与门声距离策略，没有新增AI脚步、战斗语音或真实Foley资源，**F11听感问题仍未解决**。

`src\combat-events.js`继续分离射击、弹着和爆炸反馈：伤害、弹药、AI听觉与压制仍在模拟中立即结算，表现层只消费事件生成弹道线、枪口/命中粒子、爆炸、原有声音及当前武器后坐力，不再从这些显示操作反推伤害。事件在本模拟帧内一次性消费，不增加一帧输入延迟；保留原射手/武器/载具/席位ID，延迟炮弹与阵亡后反馈不会借用新成员身份。材质命中在实际射线处保存世界位置/法线及材质类别，包括实例变换，不把网格、材质或士兵对象留在历史中。

战斗事件单帧上限1024、历史64条，超限明确报错而非静默丢弃；从首批512扩容是为同时保留射击、实际伤害和确认伤亡事实，不增加兵力或射速。暂停不重放，回大厅/新局清空，同时清理旧命中标记、受伤边缘及后坐力，避免上一局计时串入新局。显示仍使用现有粒子/灯光预算和画质开关，没有加入新音源或改变AI枪声覆盖范围，F11仍未完成。`test:combat-effects`核查真实GPU点光、石/土命中与暂停/开关，`test:control`和`test:projectiles`检查死亡/换人后爆炸来源；G1长帧、完整UI/动画解耦仍保留。

`src\combat-feedback.js`从实际伤害/确认伤亡事件生成受伤红边、命中标记与最多4条、持续5秒的击倒信息；生命、阵亡确认和个人/友军击倒数仍由模拟即时更新，不交给HUD回调。事件只存目标ID、队伍、实际扣血量/剩余生命和受击时观察者，不保留士兵模型引用。Y/F接管立即清空旧成员个人红边/标记，保留同局共享击倒信息；暂停冻结反馈，回大厅/新局清空。

有意修正：只有当前成员、当前武器对敌方的有效伤害点亮命中标记，友军AI击倒、无效装甲伤害、自己的爆炸误伤不再冒充本枪命中；旧成员延迟击倒仍保留原玩家计分和击倒信息，但不点亮新成员的标记。尸体可见性、原有侧倒姿态及12秒显示期限由士兵渲染器从生命/座位/死亡时间读取，伤亡结算不再直接改模型，不代表新增骨骼死亡动画、布娃娃或掉枪。

`npm.cmd run test:damage-feedback`要求开发服务器，在明确的5v5诊断中用正常鼠标输入产生真实步枪伤害，验证命中标记、Y清理、暂停与真实伤亡/计分；`ARTIFACT_DIR`保存来源/目标及HUD状态。脚本通过只读坐标辅助瞄准，不设置生命、伤害、位置或无敌；它不是玩家瞄准手感、AI强弱或交火性能的验收。

`src\weapon-simulation.js`按实体推进武器动作，不再在人物移动/镜头更新里推进拉栓，也不对当前载具重复更新装填。保持既有个人步枪规则：换人、收起、进入载具或死亡过渡暂停个人动作，返回有效控制后从原进度继续；已启动的车载/班组支援武器装填按战场模拟时钟完成，下车不会冻结原车的装填，空武器不会在后台自行开始装填。全局暂停不推进任何武器。

机械动作只产生带士兵/武器ID的一次性反馈事件，由当前有效视角消费；旧成员或已收起步枪的声音不能串入新视角。换队时注销原单位支援武器登记，不让反复迫击炮出击积累无主武器，也不改写其已发射炮弹的原始来源。规则覆盖100次替换及30/60/144Hz，普通输入回归覆盖下车期间完成原车装填、换人/工具打断和同局由迫击炮换成步兵。本项没有统一AI的完整弹药/装填规则、加入有限备弹或改善枪声音源，相关G4/F11仍保留。

迫击炮在飞弹由 `src\projectiles.js` 拥有起点、目标、当前位置、飞行时间和伤害，渲染网格只跟随模拟，不再由网格位置反推弹道。发射时冻结原单位/士兵/武器/载具/席位及个人或友军击倒归属；步枪、主炮、机炮和AI步枪的伤害也记录实际武器来源。换人、阵亡、撤出旧实体登记或同局重新部署不会改写已经发射的炮弹，暂停冻结其模拟；返回大厅或新局清理弹体、渲染对象及旧弹着记录。碰撞使用实际场景与载具几何，每弹只结算一次；在飞上限32、弹着历史32条，共享弹体几何和材质不逐弹销毁。

### 手动画质与独立效果

大厅可选高/低画质，战斗中按Esc在暂停菜单调整同一档位，并独立开关动态阴影、距离雾、场景烟雾、画面颗粒、冷灰日光、枪口效果、枪口点光、弹着碎屑和受伤暗红边缘。高档像素比上限1.6、方向光阴影4096、场景烟雾上限30；低档分别为1.0、1024、10。实际像素比不会超过设备值，阴影尺寸不会超过GPU限制。低档仍使用同一套PBR/天空资源，不降低兵力或改变伤害、移动、弹药与据点规则，也不声称能保证所有PC达到60FPS。

独立开关跨档保留；设置仅当前页面有效，刷新后恢复高档。切换会释放旧阴影渲染目标，并同步窗口尺寸及必要的着色器状态；当前没有自动降级或后期管线，不显示假启用状态。`npm.cmd run test:quality` 检查真实画布/阴影尺寸、烟雾数量、各开关、重复切换后的纹理数量、720p大厅以及暂停时的战局连续性。

### 冷灰日光、枪口与基础弹着

`src\lighting.js` 提供既有HDR下的冷灰日光首版：降低暖色直射、增加中性补光，关闭选项可恢复原光照。没有替换天空资源，原HDR仍有蓝天；补光降低阴影对比不等于新增真实软阴影算法，整体现实感仍需人工复验。

### 可选步枪PBR资源接口

`src\weapon-assets.js` 的 `RIFLE_PBR_ASSETS.wood/steel` 可配置本地 `public\assets` 下的贴图，浏览器路径采用 `/assets/...`。默认各通道为 `null`，保留程序化材质，不自动下载或要求外部服务。配置前应人工核对资源适用性与CC0许可证，并在对应项记录 `license: 'CC0-1.0'` 与 `source` 原始来源；配置声明本身不能代替授权审查。

可用通道为 `color`、`normal`、`roughness`、`metalness`：颜色使用sRGB，其他为线性数据；法线要求 `normalFormat: 'OpenGL'`，粗糙度读G、金属度读B，灰度图可直接使用。木托不允许配置金属度贴图；配置新木色时清除旧生成纹理的bump，避免错配。钢部件共享资源，前后视角仍使用同一枪体/材质。没有实现glTF模型替换或自动资源制作。

路径只接受本地 `/assets/`，非CC0声明、未知字段、错误法线方向或文件缺失会显示具体错误并阻止不完整资源出击，不静默回退。`npm.cmd run test:rifle-textures` 使用原始自制测试贴图检查真实加载、颜色空间、共用请求及失败提示；它不证明已制作出写实枪械表面。

### 普通步枪与封闭装甲：有限止错

敌军步枪兵识别封闭坦克后不再持续无效开枪，也不能靠普通步枪命中直接扣整车生命；会先寻找掩护、近距避让或保持警戒。伤害入口按人员当前座位归属检查武器/目标类别，下车成员恢复人员目标，不会因为玩家切回车内就让所有地面车组免疫轻武器。爆炸和当前其他武器保留原型伤害，**不是完整装甲穿深或已经拥有反坦克装备**。

### 重生与工兵：当前明确规则

这些是为约220米宽的小地图采用的**原型参数，不是《Enlisted》的原始数值**：

- 中国步兵、迫击炮组从南侧步兵集结地或工兵集结点出击；坦克从装甲出发点出击。飞机从固定的南侧空中入场点进入，尚无机场起降。
- 日军首次部署和后续增援从北侧基地进入；日军工兵建成前线集结点后，后续增援优先使用它。重生点附近有对方地面部队时不能使用；飞机飞越不触发这一地面封锁条件。
- 每方最多保留一个工兵集结点，新建会替换旧点；建造耗时6秒、耐久120，敌军在18米内阻止建造与重生。建造点须在未占领据点边缘18米以外，周围留出2.8米生成空间。地形受阻会明确显示原因。
- 开局步兵一班的第一名队员为工兵。按2取出工具，右键启用集结点蓝图，绿色可建、红色不可建；按住左键完成建造，松手或明显移动会中止。当前不保留未完成蓝图，也没有工程材料消耗。
- 集结点可被双方枪炮破坏；敌方AI会射击发现的我方集结点。摧毁后提示、地图标记和部署可用性同步更新。己方集结点跨小队阵亡保留，新一局才清空。
- 五个独立班组是小队身份，不是五个兵种：步兵一班、步兵二班、迫击炮组、装甲车组、航空小队。换人不等于换队；步兵一班覆灭后，步兵二班仍是另一个合法选项。
- 当前仅禁止立即重选刚阵亡的班组，**未实现原作所有模式的小队轮换/冷却、团队载具数量限制、多人重生排队或工兵个人建造上限**。单人原型不伪造其他真人玩家的排队。

### 当前作战规模

用户将原30人排改为**10人班**后，默认步兵开局已采用100对100：双方各10个实际单位，每个步兵单位10人，所有成员具有独立位置、生命、状态和登记出生来源。玩家控制其中一班，其余19个单位自主移动/交战；本班全灭后才换出击单位，其他友军不会随玩家重部署而重置。

玩家选坦克/飞机会占一个本方单位：分别为90名自主步兵加3人车组/1名飞行员，对方仍为100名步兵。每方载具上限2个已纳入规则，但当前尚未实现自主AI驾驶车辆，默认敌方不刷载具；不能把上限接口当成AI坦克/飞机已经完成。各种专用兵种装备仍见F28，当前步枪手/工兵不等于完整混合兵种。

单位从双方后方登记集结区安全展开，不在据点附近生成；同一自主单位须全灭、经过冷却且重生点可用才整队补充，工兵点可以影响后续入场。角色近远实例化、空间索引和AI/路径分时预算用于控制开销，远处降低几何细分和投影；近处己方枪体仍与第一人称同源。这不是已完成的人物骨骼动画、可靠大规模战术或真实历史编制。

`npm.cmd run test:population` 检查实际200名成员、20个单位、出生净空/间隔、19个自主单位的移动及实战伤亡、Y与暂停、单载具替换和真实计数，`ARTIFACT_DIR` 可保存实机画面及观测数据。当前低画质无头Chrome观测不等于所有PC或高密度正面交火都保证60FPS；敌方真正夺取/反夺控制权仍待F29，不把进入据点防守当作已经实现。

标准步枪对普通人员采用50伤害/100HP，两次有效命中可致死；友敌AI使用相同的间隔和命中概率规则，10米内中心点/遮挡判定通过后不再额外随机判空枪，间隔仍尊重拉栓周期。建筑/集结点、飞机机体与爆炸伤害不是人物伤害，未随此项统一成50。当前仍没有完整部位、姿态命中区和实际散布模拟，不把这项参数止错说成射击系统已完全写实。

### G1可复现交火与性能采样

先启动开发服务器，再设置外部证据目录运行：

```powershell
$env:ARTIFACT_DIR = Join-Path $env:TEMP 'embers-g1'
npm.cmd run benchmark
```

默认顺序运行5v5和正常100对100各两次：1280×720、DPR=1、高画质、种子1938、初始预热3秒，正常人口按W前进到南街z≤42，观察真实AI开火后采样18秒。可通过 `BENCH_REPEATS`（1–5）、`BENCH_SECONDS`（5–60）、`BENCH_WARMUP`（1–15）、`BENCH_SEED`、`BENCH_SCENARIOS=duel,full`、`BENCH_QUALITY=high|low` 和 `GAME_URL` 明确改变配置。不同批次使用不同证据目录，避免覆盖。使用固定随机种子不等于固定帧调度；自然伤亡/整队增援仍启用，完整场景没有冻结为永远200名幸存者。

开发专用URL `?benchmark=duel&seed=1938` 明确标记5v5诊断，`?benchmark=full&seed=1938`保留默认人口；`?benchmark=bridge&seed=1938`仅用于独立桥面几何检查。发布构建忽略这些参数，仍部署正常人数，不暴露写入生命、传送或无敌接口。`test:benchmark-config` 检查开发场景重开的出生记录与发布版200人边界。

每批保存环境JSON、实际源代码快照、逐帧JSON、CPU `.cpuprofile`、路线/实际人数、截图及P50/P95/P99/最大帧/长帧计数、路径队列/等待和模拟时间比例。1毫秒CPU采样有开销；函数包含时间不能相加，`renderMs`是CPU提交而非GPU计时，诊断HUD/计时器也不是零开销。初次编译、长帧与用户死亡后的活战场均保留原始记录，不从统计中静默删除。

本轮优化了重复路径边检查/平滑、空间查询字符串键及瞬时点光数量变化引发的着色器变体：高档仍最多两盏池化枪口灯，平时强度0、射击才亮，低档仍关闭。不是通过减兵、关闭交战、减小感知范围或取消门碰撞获取帧率。具体前后数据见 `TODO.md` 的G1记录；稳定60FPS、用户环境验证、长时间压力和全局模拟时钟仍未完成，不自动认为G1整体过关或进入G2。

浏览器冒烟检查默认通过本机已安装的 Google Chrome 无头运行，需要先启动开发服务器；可用 `GAME_URL` 指定地址、`ARTIFACT_DIR` 指定截图目录。它检查工兵工具、建造中断/完成/摧毁、重生来源、敌军工兵前线点及增援、射击和小队操作、阵亡后选择与确认、选择期间战斗继续、载具及重新开局；不评估美术质量或历史准确性。

- [台儿庄古城管委会：《图说台儿庄古城之西城门》](http://tezgcgwh.zaozhuang.gov.cn/xwzx/gcdt/202303/t20230328_1637009.html)：包含标注为战时西城门、粮包防御工事、浮桥、运河侧工事与战后远景的照片，也包含现代重建照片，使用时需严格区分。可支持后续西门—运河—街垒关卡的形态研究，不能独自支持全城精确坐标和尺度。
- [中国人民抗日战争纪念馆相关历史资料页：台儿庄战役](https://www.1937china.com/kzgdata/html/20250407/174402838273260413067.html)：包含战役路线图、外围阻击及巷战影像。文中关于汉阳枪的引用明确涉及川军122师，不可直接据此认定台儿庄31师全员装备同一种步枪。
