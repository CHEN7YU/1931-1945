# 烽火山河 · 浏览器玩法原型

原创的二战中国战场单人 FPS 原型。当前仅有一张台儿庄主题地图，已有扫描 PBR 材质、天空环境光与细化建筑；双方分别使用共享的国军／日军方向骨骼衣身与钢盔，载具仍是程序化原型，人物动作和长相差异尚未达到成品水平。**不是历史地形复原，也不代表《Enlisted》级别的成品品质**。未提取或复制参考视频／《Enlisted》的地图、模型、音效或代码；外部候选的来源与授权依据另有记录，未实现视频中的具体关卡。

2026-10-26确认的产品约束：**最终在PC浏览器直接运行，不要求安装客户端；只使用授权清晰的免费资源，不采购。** 2026-10-28 用户另授权最多 USD 50 用于本轮 Azure 离线图片生成，作为上述免费资源约束的明确例外，不代表获准采购外部素材。当前优先核查人物/动作/关键声音并做最小浏览器导入，随后验证一段5–10分钟的步兵品质样例，不再等待G1/G2所有基础条目完成。正式100对100目标保留，小样不冒充规模验收；原生Windows/UE5迁移不再是当前路线。最新范围和停止条件见`TODO.md`；`review-request.md`已更新为18:42起整理的第二轮复审材料，明确区分已推送版本、本地样例与未通过项，并非自动实时镜像。

## 启动

需要 Node.js 20.19+ 或 22.12+。

```powershell
npm.cmd install
npm.cmd run dev -- --port 5173
```

在支持 WebGL、硬件加速的桌面浏览器访问终端显示的本机地址。依赖安装后无需运行时访问外部美术、字体或 CDN 服务；扫描贴图及天空已随项目保存在 `public\assets`，原场景美术约9.1 MiB，当前共享人物运行子集约6.77 MiB（不含元数据／HTTP开销，不能直接当作实际网络传输量）。全军共享这份资源，不重复下载100份。本地开发服务器只监听本机；仓库已配置下述Cloudflare自动发布，线上资源版本和实际运行仍须单独核验。

`references` 为离线对照资料，不参与Vite热更新监听，避免Windows下收集/查看参考图片时的文件锁导致预览进程退出，游戏源代码仍正常热更新。

## 当前人物与双方外观

### 日军步枪刺刀与近战

日军普通步枪固定显示刺刀，近景骨骼人物、远景实例与备用程序化人物均有显示；狙击枪和十一年式轻机枪不加装。日军步枪兵在同层、无遮挡的敌方步兵约 8 米内优先停止射击，平端步枪快速接近并突刺；目标逃出 11 米或失去视线后退出近战，恢复原有战术。不会追刺封闭装甲、飞机或隔层目标。

冲锋沿用碰撞、人员避让、转身、起身、体力和涉水约束，不穿墙或直接跳到敌人身边。贴身 1.65 米内先做 0.22 秒突刺前摇，在命中时重新检查距离、朝向、姿态与遮挡，单次命中造成 65 点伤害，两次攻击开始至少间隔 1.1 秒；躲开或退远可使刺刀落空。近战不消耗子弹，不触发枪声和枪口火光，伤害／阵亡沿用原有归属与反馈。上述数值为游戏调校，刺刀为原创简化几何，并非新增史实枪型复原。

`node --test test\bayonet.test.js` 覆盖刺刀模型、冲锋阈值、前摇／冷却、落空与目标限制。开发服务下运行 `npm.cmd run test:bayonet`，检查实际日军骨骼握枪、真实 AI 冲锋／近战伤害、不同时开枪、暂停冻结与重开清理；可用 `GAME_URL` 指定服务地址，`ARTIFACT_DIR` 保存截图和观测记录。

### Azure AI 场景材质试用

2026-10-28 首轮新增三组原创 AI 材质：五处现有临街外墙的剥落灰泥、93 扇活动木门的旧木板、六处沙袋掩体的粗麻布。墙面仅替换 `west-0`、`east-1`、`west-3`、`courtyard-shop`、`canal-south-workshop` 的朝街面；其他墙体、窗框、木梁、地板、屋瓦、地面和招牌文字继续使用原有资源。首轮不改几何、碰撞、门的操作或战斗规则；三种材质跨全图共享并沿用静态合批／门实例化，木门保留原有横档和拉环几何。

第二轮限于出生区第一段街道：`west-0`、`east-0`、`courtyard-shop` 共 15 片墙脚潮痕、窗下雨痕、泥溅／霉斑；现有院落两只木箱和一只木桶改用独立旧木材质，木箱框条和铁钉补足近看细节；`(-13, 70)` 的 12 只沙袋改为共享的平滑、略收口袋身与双侧缝边。污损按实际实心墙段裁切，不跨越门窗洞口；透明图集四格边缘均检查为透明。沙袋细化模型限制在原几何外包盒以内，保留原低面数隐藏射线碰撞代理及原移动障碍；其他五处沙袋不改造型。新增装饰不占通道，不改变布置、导航、开门和战斗规则，也不消耗额外的场景随机数。

图片由 Azure OpenAI `gpt-image-2.5-flare`（`2026-09-08`）离线生成。运行资源位于 `public\assets\materials\ai-scene`：四组彩色图为 1024² WebP，法线／粗糙度为 512² 无损 WebP，另有一张 1024² 透明污损图集，共 13 张约 **3.71 MiB**。处理包含对边交叉混合与压缩后接缝差值检查；法线只是从图像高频明暗估计的轻微微表面，粗糙度为近哑光估计，**不是扫描 PBR、高度测量或史实复原**，也不保证完全消除重复图案。原始生成图不作为游戏载荷。提示词、模型版本、原图 SHA-256、逐次用量、处理步骤、运行贴图校验和与估算费用记录在 `source.json`；生成内容受 Azure 协议约束，**不标记 CC0**。两轮含先前墙面样图共五张，按检查时公开费率累计保守估算 **USD 0.073522**，不是最终账单；授权预算上限为 USD 50，不要求花完。游戏运行不访问 Azure、不包含密钥或令牌。

已有原图可直接离线重处理；需要 Python 和 Pillow，缺失时运行 `python -m pip install Pillow`。只有显式加 `--generate` 才会调用 Azure，使用 Azure CLI 的 Entra 登录，并要求传入现有端点和图像部署名；不会创建资源或修改权限：

```powershell
npm.cmd run prepare:scene-art -- --source-dir '<保存原始 PNG 与生成记录的目录>'
npm.cmd run prepare:scene-art -- --generate --source-dir '<原图目录>' --reuse-plaster '<先前墙面样图 JSON>' --endpoint 'https://<资源>.openai.azure.com' --deployment '<图像部署名>'
```

生成流程固定单张 1024²／medium、只补缺失原图、不自动重试；每次尝试先保留 USD 10 的保守预算额度，失败或不确定的请求不释放额度，并拒绝对同一失败条目自动再次付费。源目录锁防止同目录并发生成。此为单次工作流支出约束，**不是 Azure 订阅级硬封顶**，其他目录／进程的费用不在此账本中。付费请求前核对实际部署的模型／版本／按量类型／区域及 Azure 公开费率；不匹配或无法核实时停止，不把别的模型沿用为同一成本。

`node --test test\scene-art.test.js test\scene-details.test.js test\asset-audit.test.js test\surface-uv.test.js test\doors.test.js` 检查来源、贴图尺寸、污损裁切／UV、沙袋外包盒与隐藏代理射线命中，以及原有门／UV 行为。开发服务下设置 `GAME_URL` 为 `http://127.0.0.1:5183/?benchmark=interior&seed=1938`，设置 `ARTIFACT_DIR` 为截图目录后运行 `npm.cmd run test:scene-art`，通过真实移动拍摄街景、墙面、木门、货箱、窗下和沙袋，实际穿过房屋前后门，并检查 13 张贴图完整加载／解码、图集透明边缘、运行不请求外部服务及缺图时明确失败。截图使用五人友军室内诊断，**不是全编制性能验收**；`BASELINE=1` 仅用于未接入材质的旧版本采集，不是游戏里的材质开关。

现有 `test:visual` 的 `<230` 绘制调用门槛在正常编制下仍不通过，不能把室内诊断的通过当作全编制性能达标。首轮在同一随机种子、正常编制起点固定观察中，原场景约 253–259、新材质场景约 251–261 次调用；这是首轮记录，不是第二轮性能测量，活动角色也会导致逐帧波动。该问题在原场景中已存在，本轮未放宽门槛，也未声称解决整体性能。

### 双方战场喊话与必播事件

游戏已内置 **264 段 Azure AI Speech 合成男声 MP3**：国军使用普通话云健／云希／云枫，日军使用日语 Keita／Daichi／Naoki。常规台词每方 26 句，我方另有 36 句钟点方向报点，每句均有 3 种声音。台词为原创虚构对话，不是历史录音、真人声音克隆或方言／历史口令考据；中文带受支持的愤怒语气，日语采用不同男声及语速／音高调整，**不保证达到真人战场嘶喊的表演效果**。台词与日语释义见 `src\battle-voice-lines.js`，音频与生成参数、校验和、使用条款出处见 `public\assets\audio\battle-voices\source.json`。生成语音受 Azure 服务协议约束，不标记为 CC0。

附近存活步兵在推进、接敌、受压、装填、躲避手榴弹时随机喊话，按士兵固定分配音色，随位置更新左右声像及距离衰减，55 米外不播放；全局间隔 5–8 秒、阵营冷却 9 秒、个人冷却 28 秒，避免全军齐喊。车内成员、阵亡士兵和玩家本人不参与环境随机喊话。

另有 **18 段 CC0 真人无词短喊／闷哼**，来自 HaelDB 的 [Male Grunt/Yelling sounds](https://opengameart.org/content/male-gruntyelling-sounds)：三个固定音色，每类两种录音，双方共用，不冒充中文／日文母语表演。真实受击可立即概率触发短哼，近敌突击及受压状态变化可触发短喊；普通行军不持续吼叫。单独通道最多一声、全局间隔至少 1.5 秒、个人冷却 8 秒、35 米外不播放，隔墙减弱并低通；给命令／公告／报点让路，丢弃的反应不排队补播。暂停、战果及重开停止旧声音。源码为 `src\battle-reactions.js`，原始来源、选段校验和及处理信息见 `public\assets\audio\battle-reactions\source.json`；情绪匹配和实际听感仍需人工验收。

**枪声按原始射击事件选择，不靠背景循环模拟射速**：我方普通／狙击步枪分别使用用户提供的两份生成音频，详见下述“当前步枪声音”；日军步枪／栓动狙击枪使用用户指定的 `single-gunshot-54-40780.mp3`，保留约三秒完整枪声尾音，坦克机枪不套用该录音。其原作者 morganpurkis 在 [Freesound](https://freesound.org/people/morganpurkis/sounds/391847/) 提供 CC0，来源记录包含用户 MP3 与原作者预览的波形对照。双方 ZB-26／十一年式轻机枪使用用户指定 `foisal72-gun-fire-346766.mp3` 的三个 **95 毫秒单发片段**，排除原录音的连发间歇，每次真实开火只播放一段，按武器现有 0.12 秒周期发声，松开扳机不继续循环，也不变速整段连发；同轴机枪共用单发片段但按自身0.1秒周期发声。两类素材分别记录于 `public\assets\audio\enemy-rifle` 和 `public\assets\audio\machine-gun`。**机枪素材不是 CC0：索引标识为 Pixabay Content License，但源站与许可页面直接请求返回 403，公开发布前仍须补齐独立授权核查；不能作为独立音效包再分发。** 这些选用不代表历史枪型真实性或听感已验收。

重新处理需要 FFmpeg；人声压缩包读取另需 Python。以下脚本只接受已记录 SHA-256 的源文件，下载包和原始长录音不放入游戏资源：

```powershell
npm.cmd run prepare:battle-reactions -- '<yelling-sounds.zip 的本地路径>'
npm.cmd run prepare:enemy-rifle-audio -- '<single-gunshot-54-40780.mp3 的本地路径>'
npm.cmd run prepare:machine-gun-audio -- '<foisal72-gun-fire-346766.mp3 的本地路径>'
```

**18 米内的友军步兵会主动提醒狙击手、机枪手和敌军坦克**，例如“三点钟方向，敌方狙击手！”“十点钟方向，敌方机枪手！”“前方发现敌军坦克！”。覆盖全部 12 个钟点方向，以**开口时玩家相机的水平朝向**为准：12 点正前、3 点右侧、6 点后方、9 点左侧，而非队友自己的朝向或固定世界坐标；报点后的转头不改写已经说出口的方向。队友必须有 1.2 秒内的真实目视识别，且开口前再次通过原有视线／遮挡检查；仅听到枪声、旧记忆、阵亡目标、远处队友都不会触发角色报点，不给玩家隔墙透视。坦克依据实际乘车目标的封闭装甲身份识别，按整辆车去重，不能把四名车组说成四辆坦克。

战术提醒优先于环境闲聊，但不打断 X 命令和据点公告；不积压过时的方向，轮到说话时重新选择有效目标。坦克／狙击手／机枪手依次优先；全局至少间隔 8 秒，同一目标 24 秒内不重复，不同目标也受同一报点者 12 秒冷却约束。声音来自实际队友位置并沿用他的固定男声音色；报点者或目标阵亡、玩家换人、暂停及重开会停止旧提醒，恢复不重播旧方向。

**有效 X 命令每次必播，不受随机喊话冷却限制**：短按依原规则命令进攻瞄准的据点或移动并守住标记位置，长按取消命令并跟随；语音与实际命令一致。连续命令立即替换前一条指挥喊话，不排成长队。出击、开始占领、首次据点争夺、未夺取据点的占领进度清零、拿下／重新夺回据点、我方据点失去控制、我方集结点被毁、胜利、失败、平局都有事件语音；事件公告按顺序播放，不被环境随机喊话挤掉，据点公告和最终战果分别保留。暂停停止播放，恢复后重播未完成的公告，回大厅／新局清空旧语音。

**沿用 main 的三点同时争夺与反夺规则**：每个据点独立追踪双方真实控制权。我方已占据点被中和时提示“阵地失去控制”，重新夺回时再次播报拿下；尚未占领的进度归零只提示“进攻受挫”，敌军独立占点不误报为我方成功。胜败语音兼容全点连续控制与超时判定，超时持平另播平局，不把拿下最后一个据点当作立即胜利。声音依浏览器 Web Audio 和用户交互解锁；资源失败会在控制台、出击提示和状态栏明确报告，不能在浏览器禁声／资源缺失时保证可听见。

音频只在开发时离线生成，游戏运行不调用 Azure、不携带密钥或登录令牌。需要重新生成时，先用 Azure CLI 登录有 Speech 数据权限的身份，再设置现有资源信息：

```powershell
$env:AZURE_SPEECH_REGION = '<资源区域>'
$env:AZURE_SPEECH_RESOURCE_ID = '<现有 Speech 资源的完整 Azure 资源 ID>'
npm.cmd run prepare:battle-voices
```

脚本会检查区域内实际可用的男声／情绪，不自动创建资源、更改域名或授予权限；合成可能产生 Azure 用量费用，只有内容／参数和校验和都匹配才复用已完成的资源清单。`node --test test\battle-voices.test.js test\asset-audit.test.js` 覆盖台词、素材完整性、混音、冷却、事件必播、实际占领状态转换、12 钟点相机朝向、目视门槛及坦克车组去重；开发服务下运行 `npm.cmd run test:battle-voices` 检查真实 MP3 解码、X 命令、暂停／重开、双方实际音源播放、战术提醒、公告顺序与缺失资源提示。

### 日军九七式中战车

按用户更新后的编制，正常战局日军固定**10个小队：8个11人步兵班、2个四人九七式坦克小队**，共88名步兵、8名车组、2辆早期57毫米短炮型九七式中战车（Chi-Ha）。不是额外增加第11个小队。默认国军仍为10个步兵班110人；下文旧的110对110及100对100记录属于调整前基线。没有加入参考图中的自行榴弹炮或防空炮车，也没有换成1942年的47毫米新炮塔型。诊断专用场景保持原编制；主菜单与实时计数反映正常编制。

车型依据：[九七式资料综述的设计与生产章节](https://en.wikipedia.org/wiki/Type_97_Chi-Ha_medium_tank)记录1937年定型、1938年开始生产、5.50×2.33×2.21米外形、4人车组、57毫米短炮、每侧6个负重轮、铆接车体、右侧驾驶员／左侧车体机枪手和炮塔后向机枪；环形电台天线参照用户提供的第二张图片。核对日期2026-10-28。**符合车型时期不等于已证实参加1938年台儿庄战役；当前地图仍是主题玩法，未核实该战役的九七式配属，不作具体参战史实声明。**若要求严格还原该战役装备，应另核实具体部队与车型后调整，不能仅凭“九七式”的名称判断。

模型为本项目原创程序化几何，不提取或复制参考游戏的模型／贴图：三色迷彩、分段倾斜车首、铆钉、短炮与炮盾、偏置炮塔和指挥塔、环形天线、翼子板、发动机百叶、排气罩、车灯、牵引环及车体／炮塔后向机枪外形。车轮和履带按实际行驶距离运动，炮塔和炮管分别跟随模拟角度；静态部分按材质合批，几何与材质共享。不是扫描资产或照片级美术，车内未建模。

四人车组和主炮有独立实体、席位、生命、武器归属与装填时钟。AI沿按车体净空建立的地面导航推进，按完整转向包络预留车辆间距；路线额外保留10厘米余量，并对齐行驶方向再走，避免在桥头等障碍的精确切线上因微小偏差卡住。静止车辆及残骸始终作为障碍；行驶中的坦克只参与附近交通规划，若绕行代价过大则在真实碰撞约束下排队，不把几十米外的前车当成永久封路。窄路汇入时让先到者优先，后车可短距离倒车腾出转弯空间，路通后继续推进。动态车辆移动后局部刷新路线，不穿墙或传送。

**车体导航始终以当前据点为目标，炮塔独立跟踪敌人**，发现敌人不会改走追敌路线，也不会因进入30米交战距离就长期停在后方。主炮仅在有弹、射界安全且接近瞄准完成时短暂停车，单次瞄准停车最多1.2秒，两次停车开始至少间隔4秒，射出即结束停车，装填及射界被己方步兵挡住时继续推进。两车分配据点中心左右各4.5米的独立驻守位置，推进到各自位置1.25米内才驻守；间距包含停车误差及转向净空，不在桥上离中心6米处提前横向封堵后车。驻守时车体转向可见敌人，让前向机枪有机会进入射界，而不是始终侧对来敌；途中仍按据点路线推进，不为追敌改道。当前据点被攻占后立即切换下一据点，诊断快照公开目标据点、导航终点、距据点中心的直线距离及交通规划状态，不能用履带里程冒充已经抵达。炮弹沿用即时射线和有遮挡的范围爆炸，不是新增真实弹道。生命280、移速4.2米／秒、5.5秒装填、125爆炸伤害、6米范围、95米射程均为**游戏调校，不是历史射速或穿深模拟**。城市窄路仍会合法绕行，不通过加速、传送或让远处步兵原地等车来保证坦克永远最靠前。封闭装甲规则不变：步枪与手榴弹不能直接损坏它，坦克炮／迫击炮／航空及范围爆炸仍可损坏；未新增反坦克步枪、穿甲弹或弱点系统。

**车体前向机枪与炮塔后向机枪均可实射**，不是把后向枪改成虚构的前向同轴机枪。[九七式车载机枪资料](https://en.wikipedia.org/wiki/Type_97_heavy_tank_machine_gun)记录7.7毫米、20发可拆弹匣及500发／分循环射速。两枪各有独立武器归属、弹匣和时钟：每次最多5发短点射，射后至少冷却1.6秒，20发打空后换弹3.8秒；与主炮装填互不补弹、互不重置。车体枪由存活的车体机枪手操作，炮塔后向枪由存活的车长操作；缺少对应车组或车体被毁即停火，同一名车组不能同一刻兼射主炮和机枪。每挺枪在自身有限射界内跟踪目标，模型枪口与射线一致，有散布、曳光、枪口火光和现有临时小武器枪声；实际射线命中才造成伤害，墙体及其他车辆会挡弹，己方步兵遮挡时停射，不向封闭装甲或飞机扫射。55米射程、35点基础伤害、点射／冷却／换弹时间和射界均为游戏调校；冷却是点射间歇的抽象，未实现温度曲线、换枪管、卡壳或有限总备弹，枪声也不是该型号的历史录音。暂停冻结两枪的射击、冷却和换弹，重开清空旧武器。

被毁后杀死剩余车组，保留焦黑残骸及碰撞；车组清理后残骸按现有30秒策略退场。**坦克小队全灭后在下一次兵力刷新（最多约1秒模拟时间）补充**，不等待步兵的17秒冷却；每个小队只补充自己的下一辆车，不复制仍有存活车组的小队，目标始终为2个作战坦克小队。仅从各自北侧装甲出发点补充；若敌军、残骸或障碍堵住出发点则记录原因并每2秒重试，不在步兵集结点刷车或穿过障碍强行维持数字。旧残骸不计作作战坦克，因此短时可见残骸加2辆活车。暂停冻结移动、履带、装填与补充，回大厅／新局清空旧实体及显示。

**步坦协同采用局部车后掩护，不是远距离追车**：自主步兵只考虑16米内同阵营的存活坦克，车后位置必须在8米局部移动范围内，不能让距离当前推进目标的距离增加超过4米；从掩护点到威胁的方向还须真正穿过车体，不能把侧面／背面来敌算作受掩护。按实际车体朝向安排12个分散车后位置，排除被占用、不可直达或受阻的位置；坦克移动时更新位置，交火时沿用停稳、抬枪及实际射界检查，在侧方探出射击，车体仍会挡住步枪子弹。坦克过远、被毁、掉头或局部位置不可达时释放跟随，继续原有推进／冲锋或交火决策，不会后撤几十至几百米去找车。手动控制及玩家本班的明确命令不被自动协同覆盖，手榴弹避险优先。

### 狙击手与开镜操作

每个步兵班保持 **11人**：1名工兵、8名步枪手、1名狙击手、1名轻机枪手。按用户选择，将原第10号步枪手改为狙击手，不额外增员；正常战局国军10个步兵班有10名狙击手，日军8个步兵班有8名狙击手，另有上节2个四人坦克小队，双方总人数分别为110及96人。Y可切换至标有“狙”的第10号队员，补充与重新出击使用同一配装，迫击炮／装甲／航空编制不变。

参考 [Enlisted PC操作表](https://www.magicgameworld.com/enlisted-pc-keyboard-controls-and-key-bindings-guide/)（第三方资料，2026-10-28核对）的右键瞄准、左Shift屏息、左键射击、R装填与Ctrl／Z姿态键位。本项目实现按住右键开镜、圆形遮罩和中心十字分划，18度垂直视角相对72度腰射约4.6倍放大，镜内降低鼠标灵敏度；不是双相机镜内渲染，也未照搬Enlisted的界面、资产或精确参数。公开资料不足以确认其所有版本的自动拉栓细节，本项目明确采用**左键每次按下一发，随后自动拉栓**，按住不连发；拉栓暂时退镜，右键未松开时完成后重新开镜。

普通手雷保留约0.1秒短闪光、短点光、受重力与地表影响的碎屑、贴地尘团和持续约两秒的烟团。**炸药包使用独立的增强爆炸**：更大的瞬间火光、多团向上翻涌的橙红火球、扩散的贴地冲击尘环，以及更多、更快的飞散碎屑。**双方坦克首次被击毁时另触发车体中心爆燃**，包含爆炸声、覆盖炮塔的火球、碎片、贴地尘环及约5秒的上升黑烟，不再只靠残骸变灰提示击毁；这是纯表现事件，不触发二次范围伤害，不改炸药包伤害、爆炸半径、装甲判定或残骸碰撞。

烟尘使用确定性生成的不规则透明密度纹理。复用原96碎屑／18烟团／2点光池，低档32／6／0；低档仍保留火球、尘环与黑烟，减少粒子且不启用点光。尘环网格预分配并复用，不为每次爆炸新增长期网格或点光；同时交火／连环爆炸按池上限替换旧粒子，不保证每团烟都完整保留。暂停冻结，重开／关闭命中粒子效果回收。仍是有界粒子表现，没有真实体积烟、房间压力波、炮塔炸飞或建筑破坏。`node scripts\grenade-visual-smoke.mjs`保存手雷、炸药包及坦克击毁的分阶段画面、动态效果和暂停／低档预算检查，诊断画面不冒充实战。

**坦克残骸会持续喷焰，而不只是一次性火球。** 九七式和维克斯B型分别按自身后甲板位置发出窄根部、黄白火芯、橙红尖端的向上火柱，火焰随模拟时间摆动、撕裂，舱盖接缝附近另有短促喷焰。前约4秒为强喷焰，之后降低为余火，至约18秒熄火，最后烟团在约22秒前消散；这些是视觉调校值，不是两款车型的实测殉爆时长，也不把发动机后舱称作现代隔离弹药舱或虚构泄压板。效果不改变伤害、声音循环、车组或碰撞规则。

持续燃烧使用独立预分配池，不会被步枪命中／一次性爆炸挤掉：高档最多显示140米内最近4辆残骸，每车两处火源、每处3张交叉竖面和8个循环烟团；低档最近2辆、每处2张交叉竖面及4个烟团，无新增点光／阴影。火焰使用自制程序噪声着色器，不下载外部火焰素材，也不是流体模拟；多车重叠时的透明绘制仍是近似。关闭“命中粒子”立即隐藏，重新开启或重新走近按原击毁时刻继续，不从头燃烧。暂停冻结，残骸提前清理时立即移除火烟，回大厅／新局清空。`node --test test\tank-fire.test.js`覆盖两车型坐标、时间阶段、帧率一致性及池上限；开发服务下设置`GAME_URL`和`ARTIFACT_DIR`后运行`npm.cmd run test:tank-fire`，保存两款真实程序模型的分阶段／四方向诊断截图和动态预览，并检查暂停、画质切换、连续爆炸不挤掉火柱及退场清理；这些模型诊断不冒充正式战局截图。

`node --test test\grenades.test.js test\control-input.test.js test\combat-targets.test.js test\combat-feedback.test.js`检查配额、扣弹、捏弹、禁止拾取／回掷、原引信、身份、伤害反馈、碰撞及不同帧率。启动开发服务器后运行`npm.cmd run test:grenades`检查真实输入、空槽不切换／耗尽回主武器、HUD、暂停、换人落弹、靠近活弹仍不能回掷、自伤接管、站蹲卧出手高度、封闭门反弹、工程工具恢复、下车车组配额与清理；可设置`GAME_URL`、`ARTIFACT_DIR`和`BROWSER_CHANNEL`（默认`chrome`，Windows可选`msedge`）。几何及车组诊断不等同于全军交火性能验收。

## 当前步枪声音

我方普通步枪和狙击枪分别采用用户提供的两份ElevenLabs生成MP3的单发主声段：0–0.42秒／0–0.28秒，转单声道24kHz PCM16、降低7dB并淡入淡出。后段瞬态不与现有按动作定时的拉栓声叠放；不改装填时钟，也不声称已经人工听验或保证生成片段内容完全分离。来源文件哈希、剪辑及使用请求在`public\assets\audio\friendly-rifle-generated\source.json`和`PERMISSION.txt`，**不是CC0或经独立核实的商业发布授权，也不是二战实录；AWP仅是用户素材描述，不把它当历史枪型证据。**

日军栓动步枪与双方轻机枪已按用户指定素材使用独立录音，同轴机枪共用机枪单发片段，详见前文“双方战场喊话与必播事件”。未分类旧事件保留[kurt的CC0实录枪声](https://opengameart.org/content/gunshots)0.6秒临时片段。该原始枪型未标明，**不是已核实的中正式／日军具体步枪录音**；源录音有部分削波，归一不恢复已丢信息。原28,844字节WAV及许可／哈希仍在`public\assets\audio\recorded-rifle`。

各类片段共用同一个有界混音器，按真实开火事件的阵营与武器类别选择，不把新步枪声套到日军或机枪。非本人枪声采用3米近区、反距离衰减，距离越远越小、越闷，180–240米平滑淡出。听音范围不改变180米武器伤害距离或AI视野。相同距离的友军／敌军使用相同响度规则；5／25／50／100米相对本人约低5.5／13／18／23dB（滤波前）。左右声像随观察方向更新，换人后旧枪声不保留个人增益；本人合法操作的车载次武器也须同时匹配士兵与武器身份。

最多8个非本人声部、每绘制帧最多新建3个；同一帧所有模拟子步的原射击事件一起按本人、预计响度和距离排序，声部满时近处新枪声可替换更弱的尾音，不因远处事件先到而丢掉近处声音。新局清理旧尾音和待消费事件。枪声独立总线使用线性至0.85、输出小于0.95的对称软限幅，不改变普通单发波形；极端密集叠加仍可能产生饱和音色，不冒充透明动态压缩或整个游戏所有声音均无削波。没有建筑声学遮挡、传播延迟或最终混音。录音加载／解码失败仍明确提示并保留原合成声；坦克主炮、爆炸、脚步和机械声不经过这条枪声限幅链。

玩家本人步枪在上一轮提高3dB后再提高2dB，相对最初混音共提高5dB（线性增益约1.778倍），不提高共享总线或改变机械声／脚步音量；不是对真实危险枪声响度的复刻。`npm.cmd run test:rifle-audio`检查实际玩家／NPC播放与明确降级；开发服务器上运行`node scripts\rifle-mix-smoke.mjs`另以真实录音验证各距离浏览器实际输出、本人额外2dB、左右声像和九声部同步峰值，后者是合成极限检查而非战斗性能／人工听感验收。`GAME_URL`指定开发服务器，`ARTIFACT_DIR`保存观测。

`/audio-study/`是仅供本地开发试听的新音源对比页：当前片段、Arisaka近距和莫辛近距，各0.6秒，恒定增益匹配RMS电平，统一试听音量，不额外压缩或变调。新候选来自[The Free Firearm Sound Library](https://opengameart.org/content/the-free-firearm-sound-library)，明确CC0、可免费商用；来源、原／处理后SHA256和限制在`audio-study\assets`。**用户试听后认为B／C不如当前A，两份新候选未采纳，暂保留现有音源；这不是对A音色的最终认可。**Arisaka源库标注.30-06，并非已核实的原装三八式；莫辛也不是中正式。两者都是枪手前方而非射手耳位，处理后源文件存在满刻度样本；RMS相等不保证听感等响。此页不加载游戏，也未替换正式音源，Vite默认生产入口不打包该目录。使用`node scripts\prepare-rifle-candidates.mjs <解包目录>`从已校验原件重新生成，`node scripts\rifle-candidates-smoke.mjs`检查浏览器播放／解码与明确失败；服务器及观测目录同样用`GAME_URL`／`ARTIFACT_DIR`指定。

**旧 A/B/C/D 试听轮次已暂停：这些候选均未通过音色验收。**A太闷、缺少利落的爆裂感；B／C不如A；D的均衡处理也未获认可。本轮我方普通／狙击步枪已另外指定上面的两份生成音频，日军步枪与双方轻机枪也按另行指示替换；旧试听页仅保留记录，不代表新素材已获最终音色验收。D曾作70Hz高通、350Hz削减3dB、3.2kHz提升3dB并匹配电平，不增加压缩或变调，也不会修复原录音削波或确认未知枪型；未接入游戏，不能把频段能量变化当作人工音色认可。

### 步枪机械操作声音

控制士兵的步枪已接入解锁、后拉枪栓、装填、闭锁四份CC0拟音，WAV共51,776字节；开一枪听拉栓，按R听装填即可试听，不需打开独立素材。只消费原`weapon.mechanical`动作事件，不在扣扳机时提前播放整套声音，也不改变弹药、射速或动作时序。每绘制帧最多启动3个、同时最多4个声部；换人、死亡、暂停、收起步枪及入座停止原队员尾音，新局清理事件序号。只播放当前士兵和当前武器的个人声，不把友／敌AI机械事件当作近耳声。

来源为[LFA的混合机械录音](https://opengameart.org/content/equipment-clicks-iii)及[BMacZero的装填音效](https://opengameart.org/content/gun-reload-sound-effects)，均明确CC0，可公开仓库及浏览器分发。LFA原录音混有步枪、订书机和卷尺，单个片段物体未经核实；这不是已验证的历史步枪实录，也不是弹壳落地声。来源、原始哈希和处理记录在`public\assets\audio\rifle-mechanical`；听感与战场混音仍待人工复验。任一文件加载或解码失败时控制台、HUD及出击提示明确告知，并使用原合成机械声，不关闭其他枪声和脚步。`GAME_URL`指定开发服务器后运行`node scripts\rifle-mechanical-game-smoke.mjs`检查正式游戏播放、暂停／换人／切工具／车组切换、新局及HTTP／解码失败路径；`ARTIFACT_DIR`可保存观测。

### 地表脚步录音

控制士兵的站立／蹲行接触及落地使用已在库的 [Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds) CC0录音：石地用 `concrete.ogg`，木地板用 `wood.ogg`，泥地暂用 `grass.ogg`。三份原文件共20,047字节，复用诊断页已有文件，不新增下载副本。浏览器内按24kHz解码、混为单声道，从原接触起点保留最多0.11／0.14／0.16秒，去直流、限制峰值并淡入淡出，避免长尾叠响；原文件与哈希不变，处理及来源记录在 `public\assets\audio\kenney-impact\source.json`。

声音继续消费实际位移产生的 `movement.footstep`，使用事件捕获的原士兵、地表、姿态和速度，不按墙钟另造落脚、不反读渲染骨骼，也不调整移动规则。速度、蹲行和落地只改变接触音量／滤波，轻微音高变化不改变落脚时序。每绘制帧最多启动2个接触音、同时最多4个，暂停、换人、入座及新局会停止旧接触尾音；追赶积压时可能舍弃超预算声音，而非密集补播。

这是每种地表一份录音的基础辨识改善，**不是完整军靴拟音或听感已验收**；泥地的草地代用品仍需替换，匍匐保留原合成摩擦声，友／敌AI脚步尚未接入同样的完整事件路径。加载／解码失败时控制台、HUD和出击提示明确告知，保留原合成脚步，不影响步枪录音。`npm.cmd run test:footstep-audio`需要开发服务器，`GAME_URL`可指定地址，`ARTIFACT_DIR`可保存观测与截图；三种地表路线是明确标注的无敌军几何诊断，另查正常100对100启动和实际枪声，不当作规模性能或人工听感验收。

### 只读资源发布检查

`npm.cmd run audit:assets`核对 `public\assets` 显式登记的各组来源清单中的运行／诊断文件，检查缺失、空文件、大小、原SHA256／MD5，以及未登记的新增素材。`npm.cmd run build` 后运行 `npm.cmd run audit:build`，再比对构建副本的SHA256并拒绝未审查的额外产物，输出文件用途、大小和校验清单；任一完整性错误会以非零退出。它不访问线上、不删除文件，也不自动证明来源文件中的授权陈述合法或充分。国军人物仍明确标为用户转述作者电话许可，不会被统一归为CC0；文件包含旧动作曲线也不代表正式游戏在播放该动作。

当前构建仍复制6个人物诊断文件，共1,402,646字节（约1.34 MiB）。机械音效已接入主游戏并显式改列运行资源，来源限制与接入说明见`references\rifle-mechanical-audio.md`。构建检查会明确警告诊断文件夹带；这不是主游戏实际请求量，也不是已完成生产包清理。该批只检查并保留既有诊断页路径，不移动或删除其素材。新增正式素材、改变批准用途或许可方式时须显式更新来源记录和检查分组，不会自动放行未知候选／原始压缩包。

## Cloudflare 部署

项目使用 Cloudflare Workers 静态资源托管。根目录的 `wrangler.toml` 明确指定上传 `dist`，无需 Worker 入口代码或 `@cloudflare/vite-plugin`，也不改变本地 Vite 启动和预览方式。只发布构建产物，不上传 `src`、测试或 `references`；`public\assets` 会由 Vite 复制到 `dist\assets`。

在 Cloudflare 的 Workers Git 集成中连接本仓库，根目录使用仓库根目录，并配置：

| 设置 | 值 |
| --- | --- |
| 构建命令 | `npm run build` |
| 部署命令 | `npx wrangler deploy` |
| Worker 名称 | `1931-1945`，与 `wrangler.toml` 一致 |
| 生产分支 | `main` |

确保 Cloudflare 构建的分支已包含 `wrangler.toml`。如果使用其他 Worker 名称，同时修改该配置中的 `name`。不要在构建时自动接入 Vite 插件：缺少明确的 Wrangler 配置时，自动接入可能因现有 Vite 配置没有 `plugins` 数组而失败。

也可以在本机完成 Cloudflare 登录后发布：

```powershell
npm.cmd ci
npm.cmd run build
npx.cmd wrangler login
npx.cmd wrangler deploy
```

仅检查打包和部署配置、不上传资源时，使用 `npx.cmd wrangler deploy --dry-run`（先运行构建）。部署在域名根目录，以保持 `/assets/...` 路径有效；未配置 SPA 回退，缺失资源返回404。发布后仍是桌面 WebGL 单人游戏，不会新增后端、多人联机或跨刷新存档。

### 负重移动：当前调试规则

这些是本项目的米制调试值，不是《Enlisted》实测参数。WASD默认慢跑，按住C慢走；站立向前移动时Shift冲刺，举枪时Shift仍为屏息。步兵速度为慢走1.75、慢跑3.15、冲刺4.8米/秒；迫击炮搬运分别为1.4、2.45、3.7米/秒。倒退更慢，蹲、卧、举枪另有速度限制。

移动有加速、制动与转向惯性。脚步、镜头和枪身基于碰撞后的实际位移驱动；顶墙不持续踏步，松键后有短暂制动。步频约为慢走2.3、慢跑3、冲刺3.6次触地/秒。枪身随步态、转向和冲刺产生滞后；冲刺后举枪需要约0.45秒恢复，其间不能立即开火。

冲刺持续消耗体力，耗尽后暂时不能冲刺，恢复到35%才解除疲劳限制。每个队员独立保留体力；非控制队员缓慢恢复，Y来回切换不会补满原队员体力。跳跃也需体力。控制士兵接触声已按石板／木地板／泥地切换CC0录音，泥地为草地代用品、匍匐仍合成，详见“地表脚步录音”；友军已有基础骨骼低步态，完整装填、受击等动作仍未完成。

B在标准/减弱/关闭镜头步态之间切换，暂停菜单也可选择；只减弱镜头步态，不取消必要的瞄准、后坐力与枪械动作，也不改变速度或体力。此设置在当前页面内保留，刷新后恢复默认。

`npm.cmd run test:movement` 使用真实键鼠输入检查移动、体力、冲刺转瞄准、顶墙与舒适度开关，另用确定性的20米/50米空场模拟验证30/60/144FPS一致性。设置 `ARTIFACT_DIR` 时额外保存1440×900实机录像与测量JSON；录像需要Playwright的FFmpeg组件（缺失时按其错误提示安装），不设置该变量则无需录像编码器。技术结果不代表F2手感已通过用户复验，进度见 `TODO.md`。

### 第一人称步枪：当前实现与限制

本轮原创样枪采用中正式/Type 24风格，以帝国战争博物馆[1936年巩县藏品 FIR 7135](https://www.iwm.org.uk/collections/item/object/30029566)记载的全长111厘米、枪管59厘米作为比例参照；[1944年藏品 FIR 8276](https://www.iwm.org.uk/collections/item/object/30032572)记载110/60厘米，不能把不同藏品数值混为一件实物。馆藏文字确认其与Mauser Standard Modell的关系，但页面没有可公开查看的实物图像；**尚未完成外观逐项实物对照，也没有确认当前台儿庄小队的具体配枪**。因此界面标为“比例样枪”，不是精确历史资产。

第一人称与己方第三人称使用相同的枪体/枪栓几何与材质；第一人称另外添加手部及动作层，第三人称仍是简化持枪姿势。新模型有连续变化截面的木托、倒角机匣、开口机匣/枪栓、枪管箍、V形照门、准星、护圈与背带，以及原创生成的胡桃木纹、发蓝钢材、布料表面。静态部分按材质合批并共享缓存。肩—肘—腕使用两段程序化求解，上臂约35厘米、前臂约34厘米，袖子有肘部、收口和体积，不再用一根过长直筒连到枪上。手指仍简化，**不是完成的蒙皮人物、专业烘焙资产或生产级LOD管线**，整体观感仍待复验。

射击后有0.65秒开锁、后拉、复进与闭锁动作；未闭锁不能再次发射。R可在拉栓时排队装填，随后执行2.7秒装填；弹仓空时展示五发桥夹，部分弹仓展示逐发补充。弹药仅在动作结束后一次性提交，尚非逐发中断/膛内弹完整模拟。暂停冻结动作；当前控制者收起步枪／入座时暂停个人动作。Y交给AI的原成员现在会继续自己的拉栓／装填，接回时保留其真实剩余弹药和动作，不因换人补满或重置。机械操作使用上述通用录音反馈，失败时明确提示并保留合成降级；短时枪口焰与抛壳表现保留，角色动画、历史音色和人工听感并未因此通过验收。

举枪用模型照门缺口与准星尖端对齐视线，射击从实际枪口向瞄准目标求交；近距离遮挡以枪口射线为准，不能只凭摄像机可见就穿墙命中。靠墙会回收、放低枪械并退出瞄具，受阻时明确提示且不能发射；移开后恢复。当前为即时射线枪械，没有重力、弹道下坠、风偏或历史归零模拟。

### 敌我AI步枪火控

两方AI共用每发合法射击的基础命中率：10米50%、20米25%、40米10%、60米3%、75米1%，中间连续线性插值，0米上限55%；受压统一乘0.55，近距离也不再保证必中。多人集火仍会危险，不把概率下降解释成玩家无敌或保证存活时间。玩家仍按实际枪口射线手动命中，没有额外命中率抽签；共同步枪射线最大180米，AI视觉／确认射界仍75米。敌我人体伤害见下节，已经不再沿用一律50的旧规则。

AI开火须实际停步（速度不超过0.1米／秒）、结束冲刺恢复、完成姿态过渡。首发仍需对同一目标连续确认射界并基本瞄准至少`0.45 + 0.65 × min(距离,75)/75`秒，受压再加0.25秒，不是一发现就瞬发。35米内同目标步枪可在0.65秒拉栓和约0.15秒复核后继续开火，轻机枪保留三发短点射。35–75米不禁射，但首发之后每发需连续稳定瞄准6–10秒，按距离插值，受压再加0.5秒；远距轻机枪也不连续点射。换目标不能绕过已产生的远距后续长瞄；靠近后恢复近距节奏。35米、6–10秒是本项目体验参数，不是历史实测或原作内部规则。

每次约0.1模拟秒复核视线／枪口遮挡及友军挡线，视觉确认断档超过0.2秒、失去射界、走动或换目标会重新瞄准，不从实时隐藏坐标补充记忆。双方使用本人的步枪／轻机枪弹仓，真实扣弹、按各自周期拉栓／循环与空仓装填；攻击敌方集结点也不能绕开。玩家手动180米射程、部位伤害和原命中概率曲线不改。

AI仍先按上述概率判断有效射击，再从真实枪口向已观察点求人体交点，并复查环境遮挡；不是已完成的真实散布弹道，未命中抽签的弹线仍可能指向目标。第三人称完整拉栓／装填动画和有限备弹也未完成。`node --test test\ai-rifle.test.js test\combat-targets.test.js test\weapon-simulation.test.js`覆盖规则，`ARTIFACT_DIR`指定目录后运行`node scripts\ai-rifle-smoke.mjs`记录实际开火、装填和暂停；新版一枪失能改变交火／装填样本的出现频率，不用复用旧生存率结论。

### 人体命中区与伤害

敌我共用16个人体椭球代理，区分头、躯干（含骨盆／颈）和四肢。步枪头／躯干有效命中100伤害、满血失能；四肢40，满血首中剩60。只结算射线最近的实际人体交点，不凭世界高度或随机标签判部位，不把背后的预选目标冒充实际受击者。枪、钢盔外沿、背包和衣服轮廓不是人体代理；擦到装备而没进入人体不扣人血。这不是钢盔防弹或材料穿透模拟，穿过被忽略的外观后真正进入头部仍按头部命中。

原生人物从同一待机／走跑／单膝／卧姿／侧身与携枪流程采样身体关节；每方最多一套不绘制、可复用的独立姿态视图，按需更新人体代理，不从近景池或上一帧显示网格反读，也不为200人新增200套骨架。近远LOD、低画质或自身身体隐藏不改变伤害判定。程序外观对照模式使用独立的姿态代理；人物外观资源及原程序渲染器保留，不把简化椭球称作蒙皮逐三角面命中。封闭载具／飞机的步枪限制不变；爆炸等其他武器伤害数值不改，尚无断肢、持续流血或新倒地动作。

`test\soldier-hit-zones.test.js`核查装备擦边、姿态／朝向／180米边界及显示层隔离。`scripts\soldier-hit-zones-smoke.mjs`比对两方真实关节、手臂可达、抬枪／低携枪与人体交点，`scripts\rifle-hit-zones-smoke.mjs`通过普通鼠标射击分别核对头／躯干100、四肢40，`scripts\soldier-motion-smoke.mjs`记录战场连续转向与实际枪管方向。诊断均需`ARTIFACT_DIR`，不改实际士兵位置、生命或弹药来制造通过。

### G2实体归属、地面上下车与阵亡过渡

`src\entities.js`为单位、士兵、武器、载具和座位提供稳定ID。士兵持有位置/朝向、生命和个人步枪，坦克/飞机持有自身位置/车体状态、座位和主武器；当前控制器只选择所属单位和士兵ID。原`unit`接口是派生兼容视图，场景模型跟随模拟位置，不再用模型位置作为地面士兵/载具的唯一状态。不是全量ECS或完整渲染/模拟分离，角色局部动画、部分弹道/表现和UI仍有后续工作。

`src\vehicle-renderer.js`按载具ID管理坦克/飞机视图，从实体位置、车体朝向/俯仰/侧倾及炮塔角单向投影；载具模拟不再持有或直接变换模型，网格仅标记`vehicleId`供几何查询回查。每次模拟载具移动后同步实际射线几何，残骸保留到登记实体退休，重开/退出移除视图但不销毁共享资源。坐车人员、当前受控身体和地面尸体的显隐也由士兵渲染器从实体状态派生，不以旧`model.visible`反推控制或生命；没有新增正式车体、美术破坏或骨骼动画。

坦克中按F可从安全出口下车，原车不消失，原士兵恢复独立步枪；近距离看向原车再按F返回空席。检查墙、车体、其他车辆及人员，全部受阻则不改变座位/位置。当前只允许原车组返回原车，未实现接管其他单位车辆、全车组撤离指令、空中离机/跳伞、装甲车和野战炮席位。完好遗留车继续计入载具上限，不能反复下车刷车。

Y选择本车组存活成员，可以从地面成员接管仍在车内的成员，反之亦然；个人步枪、车载主炮和机枪各自保留弹药／动作，车体生命不刷新、冷却不缩短。车长／炮手可操作主炮和Space并列机枪，驾驶员只能观察／驾驶，不能以空格或鼠标越权开火；机枪和车体／炮塔方向图已接入。车长／炮手／驾驶员眼高为车体基面上1.88／1.72／1.3米的原型参数，不是历史观察窗测绘；前两席还采用炮塔中心的实际模型偏移。专职机枪手、AP/HE和完整驾驶权限／视野仍待F12/F26，不能称为完整坦克模拟。

`src\control-transition.js`在确认阵亡后进入独立`transferring`状态，显示暗红/阵亡提示，约0.6秒在全暗遮罩下重新选择本单位存活成员，约0.9秒恢复操作；均为本项目调试值。过渡清理输入，Y和长按射击不能提前操作新成员，战场/AI/载具/炮弹继续；Esc暂停冻结时钟，重开/回大厅清理，不采用跨局定时回调。接管后不补血、补弹或继承旧死亡红边；关闭红色效果不改变接管时间。无存活成员进入原覆灭部署。倒地救援、完整死亡动作和所有连续伤亡边界仍需专项验收。

`npm.cmd run test:control`要求开发服务器，使用显式 `?benchmark=control&seed=1938` 小样例（两组自主友军、一辆坦克三人及敌军），以普通输入验证身份/资源、上下车、驾驶员主炮限制及真实自方炮弹爆炸触发的死亡—暂停—接管链路，不使用伤害/传送/无敌接口。设置`ARTIFACT_DIR`可保存实际操作JSON和截图。发布版忽略诊断参数，默认仍为100对100。

控制诊断的坦克登记点位于`(10, 83)`，用现有东侧商铺真实遮蔽下车出口，避免长操作流程依赖暴露成员偶然幸存；敌军人数、伤害、正常AI和自主友军保留。它不是交火性能或敌军无法伤害下车人员的证据，正式重生点未改变。

当前控制链另由 `src\control-input.js` 绑定单位/士兵/载具/席位/武器ID和版本，离散命令同步执行，不额外等待一帧；旧版本或重复命令明确拒绝。Y/F改变控制对象、死亡、暂停和重开会清空按住的移动/鼠标/命令计时，**换人后需重新按下移动、举枪或开火**，避免原成员的持续输入误操作下一成员。车组下车后的个人守位使用安全出口本身，不重复叠班组偏移进入车体。

控制绑定区分实际成员/席位/武器变化与同一控制者暂停后恢复：真正交接时先在模拟侧收起工具、清理当前控制者的跳跃瞬态和未完成建造，再同步新成员个人步枪的兼容装填时钟，随后才通知模型/HUD刷新。相同控制者恢复仍让旧输入失效，但不重置其已选工具和冻结中的跳跃；建造蓝图仍按原暂停策略取消。界面刷新只读实际工具选择，不再用换模型来决定装备、跳跃或步枪弹药/装填状态。

`syncControlledRifleTiming()`不推进动作、不补弹，只同步当前个人步枪剩余装填时间；车载/班组武器仍保留自己的时钟。只读`controlBinding`记录最近一次绑定在表现消费前的状态，`controlSimulation`公开当前控制瞬态快照，不提供关闭反馈或修改游戏的测试接口。普通输入覆盖锤子状态下Y、跳跃中F入座、空中暂停恢复和返回正在装填的成员；跳跃仍是现有原型控制瞬态，不代表完整第三人称跳跃物理。

AI普通步枪交火的枪口由士兵位置、朝向与阵营的既有局部偏移计算，不再读取角色模型矩阵或缩放；保持原1.39米站姿发射高度、友/敌不同枪口长度、遮挡检查、射击间隔与伤害参数。移动只更新位置、朝向和按实际位移推进的步态相位，渲染器读取该状态设置原有腿部摆动；初次移动前保持中立腿姿，停步/尸体保留既有相位表现，不额外推进模拟时间。

显示与玩家射线目标共用`syncSoldierModelPose()`单向投影：查询实际人物几何前也从当前模拟姿态同步，不隐含依赖上一帧已经绘制。规则用例比较两队不同朝向/桥面高度与原矩阵结果，并验证没有模型也能计算AI枪口、近/远LOD一致、投影不改生命/位置/步态及未渲染时实际网格可命中。第一人称枪口与射线仍使用几何适配；本项不是骨骼瞄准、真实第三人称跑姿或完整蹲卧命中区。

AI的战术位置输入现在只取最近一次观察的副本，不再因仍持有目标引用，就每步读取其真实位置来选掩体、侧移或转向。视觉记录目标身份/类别及已见位置，保留5秒；声音只记录带原有误差的声源位置，保留3秒，不借用实时目标身份。当前目标准备开火时仍需真实视线复核，成功后才刷新观察并对准实际可见位置；失败不刷新位置或延长记忆。复核后再次检查武器适用性，避免人员刚入座封闭装甲时沿用旧人员分类。

记忆过期在每个活着的AI更新中执行，不再等待有限感知预算；过期同时释放对应掩体占用、清掉旧目标和排队/已算路径，随后按命令或新观察行动。允许AI短时朝旧观察点搜索，不是失去视线就立刻忘记，也不保证看到一次后始终追踪当前位置。`test:perception`在正常规模战局用原坦克、普通W/A/D驾驶完成发现、真实几何遮挡、遮挡后继续移动与重新发现；使用已有封闭装甲规则，不改生命或传送。只读观察时间、类别、身份、实际战术点及已有视线查询结果用于核查，没有增加额外透视查询或可写测试接口。该观察边界项没有顺带实现防空武器；F32普通步枪止错及未完成部分见下文。

F32后续已补普通步枪对飞机的适用性止错：步枪AI在目标排序截取前排除飞机，不挤掉可交战地面目标，也不取消对封闭装甲的警戒。实际人员/机体伤害入口共同阻止步枪对飞机及座内飞行员扣血；手动对空射击仍正常消耗弹药并产生物理接触表现，但不算有效伤害。普通步枪对地面人员的伤害不变，已有机炮、主炮、爆炸及飞行事故仍沿用各自原型规则，不把飞机设为全局无敌。

`npm.cmd run test:aircraft-rifle`使用正常规模战场的原飞机和普通操纵，验证进入敌军候选范围后不被步枪锁定/扣血，机体及座内飞行员生命保持、随后真实坠毁和正常地面交火仍有效；规则/实际网格用例另验真实机体射线命中与离席类别变化。专用高射机枪尚未实现，其他武器对空适用性的完整设计、敌方自主飞机和飞机F离机仍待各自专项，不将本批止错称为完整防空系统。

友军接敌移动首批：已选择真实可达掩体后，接近与射击探身分开，较长的进掩体路段及受压制回撤可使用个人负重对应的冲刺速度，不再统一以1.8米/秒慢移。实际冲刺位移才消耗体力，复用玩家的消耗/延迟恢复与疲劳规则；体力不足降为慢跑，Y不补满。移动中保持行进朝向，不一边奔跑一边始终面向敌人射击；友军须停稳且冲刺后的举枪恢复结束才允许实际步枪发射。整个受压制窗口优先回到遮蔽点，不因进掩体超过1.4秒就提前探身。

仍有保护的掩体不会仅因当前探身射界暂时丢失就被重新选择；短暂承诺已选路线，受伤可提前重评，新路线也清掉旧排队路径，避免旧路径覆盖新目标。使用原实体生命、真实墙门碰撞、导航与有限感知，不提高生命、忽略遮挡或瞬移。`npm.cmd run test:friendly-tactics`在正常100对100战局通过普通W前进后观察实际冲刺/体力、至少两人贴近掩体、受压制回撤和真实停稳射击；只读`friendlyPositions`保存实际移动及最近一次开火快照，不提供可写游戏接口。

这只是进掩体/回撤/射击切换的改进，**不是完整分组掩护跃进**。协同试验未在正常实战可靠完成，因此未保留未验证的协同逻辑；掩体链、谁掩护谁及伤亡/命令中断仍待M4。第三人称仍为原程序腿摆，不是正式跑姿；敌军主动反夺点与胜负规则也未在本项改变。

门的物理/交互回归使用开发参数`?benchmark=interior&seed=1938`：原地图与正常生命、5名友军及真实队友AI，登记在原南侧位置，无敌军或自主友军交通。该场景避免把“玩家走到门前之前没人开过门”当作正常战场保证，仍验证闭门弹击、扫掠阻挡、暂停及队友接到室内命令后自行开门；不算交火/人口性能证据。发布版忽略该参数，仍为100对100。

蹲卧选择与个人观察俯仰现在属于各士兵，通过 `createControlPoseView()`读取；Y使用新成员自己的选择，返回原成员恢复其原值，不再把上一人的低头/趴伏直接带给下一人。相机接管即取对应眼高，继续使用当前桥面/坡面支撑。地面观察俯仰与原车炮塔的原型瞄准角分开，上车不会把步枪的低头角覆盖给主炮，Y/F/阵亡接管均读取原车状态；飞机俯仰/航向属于飞机实体，保留既有限幅。成功入座仍按原规则结束个人蹲卧，离车为站姿；失败入座不改原姿态。刷新视角不再写回这些角度或姿态。

这只完成控制状态归属，并非士兵骨骼蹲卧/命中区、正式炮管俯仰或四岗位独立观察装置；车长/炮手仍共用原型主炮瞄准，F12/F14继续保留。跳跃、后坐力和镜头缓动仍按原规则在交接时清理。`test:bridge`覆盖站/蹲/卧跨成员恢复及桥面眼高，可用`ARTIFACT_DIR`保存实际状态记录；`test:control`同时检查地面观察角不污染原车瞄准角和死亡接管。

驾驶员观察已独立存于原车驾驶席，相对车体转向跟随；鼠标观察不会再转动炮塔或改变主炮俯仰。驾驶员不能用左键发炮或用R启动主炮装填，右键不进入炮手放大瞄准，隐藏主炮准星/第一人称炮口模型并显示岗位限制。Y返回该席恢复其观察，车长/炮手仍读取原炮塔状态；F换席不清空这些状态，WASD驾驶规则未改。当前驾驶观察仍没有正式观察窗、设备位置/遮挡及机械限位，不能视为已还原参考图。

武器视图可见性按控制阶段及席位统一判断：阵亡移交期间新成员的武器也保持隐藏，到可操作时才显示；若连续伤亡后只剩驾驶员，接管完成也不会误显示主炮。`test:control`以实际两次近距炮击覆盖车长、炮手相继阵亡与驾驶员接管，以及驾驶观察/转向/装填限制，不使用伤害或传送写接口。

`src\control-events.js`将换人、上下车、死亡阶段、装填提示、工具视图、建造通知及本地脚步/门声反馈经有限、一次性事件交给表现层，不在下一局回放旧事件；命令轨迹32条、反馈历史64条，窗口仅公开只读快照，不提供重放/伤害写接口。语音、世界对象装配等仍有后续工作，不宣称已整体重构。`test:control`同时检查按住左键/W再Y切到车内时，坦克不自动行驶或空炮装填，原士兵和主炮资源不刷新。

实际移动/落地先记录士兵/单位ID、位置、地表、速度、姿态及落地标志，播放脚步只读该快照，不借用后来切换的队员姿态/地表；已失去控制或入座的旧脚步不在新视角播放。门的真实开/关请求记录门ID、位置和请求方向，不伪称是当前玩家开的门；F仍在接受输入时消费反馈，AI请求在同一模拟帧消费，门动画、堵塞、碰撞和导航不等待音效。暂停不重播，重开清空历史，不记录门/角色模型引用。

`test:movement`、`test:bridge`、`test:doors`覆盖正常步态/地表、桥面落地、F即时请求、AI开门和暂停/重置；`ARTIFACT_DIR`可保存脚步快照与玩家/AI门请求记录。事件解耦时沿用原合成音源；后续控制士兵接触声已替换为上节的CC0录音，门声距离策略保持，没有新增AI脚步或战斗语音，**F11整体听感仍待人工复验**。

`src\combat-events.js`继续分离射击、弹着和爆炸反馈：伤害、弹药、AI听觉与压制仍在模拟中立即结算，表现层只消费事件生成弹道线、枪口/命中粒子、爆炸、原有声音及当前武器后坐力，不再从这些显示操作反推伤害。事件在本模拟帧内一次性消费，不增加一帧输入延迟；保留原射手/武器/载具/席位ID，延迟炮弹与阵亡后反馈不会借用新成员身份。材质命中在实际射线处保存世界位置/法线及材质类别，包括实例变换，不把网格、材质或士兵对象留在历史中。

战斗事件单帧上限1024、历史64条，超限明确报错而非静默丢弃；从首批512扩容是为同时保留射击、实际伤害和确认伤亡事实，不增加兵力或射速。暂停不重放，回大厅/新局清空，同时清理旧命中标记、受伤边缘及后坐力，避免上一局计时串入新局。显示仍使用现有粒子/灯光预算和画质开关，没有加入新音源或改变AI枪声覆盖范围，F11仍未完成。`test:combat-effects`核查真实GPU点光、石/土命中与暂停/开关，`test:control`和`test:projectiles`检查死亡/换人后爆炸来源；G1长帧、完整UI/动画解耦仍保留。

`src\combat-feedback.js`从实际伤害/确认伤亡事件生成受伤红边、命中标记与最多4条、持续5秒的击倒信息；生命、阵亡确认和个人/友军击倒数仍由模拟即时更新，不交给HUD回调。事件只存目标ID、队伍、实际扣血量/剩余生命和受击时观察者，不保留士兵模型引用。Y/F接管立即清空旧成员个人红边/标记，保留同局共享击倒信息；暂停冻结反馈，回大厅/新局清空。

有意修正：只有当前成员、当前武器对敌方的有效伤害点亮命中标记，友军AI击倒、无效装甲伤害、自己的爆炸误伤不再冒充本枪命中；旧成员延迟击倒仍保留原玩家计分和击倒信息，但不点亮新成员的标记。尸体登记、松手／落枪和180秒／120具保留策略见“倒地与尸体保留”；渲染器不再独立设置12秒消失计时，不把本次程序化倒地称作布娃娃。

`npm.cmd run test:damage-feedback`要求开发服务器，在明确的5v5诊断中用正常鼠标输入产生真实步枪伤害，验证命中标记、Y清理、暂停与真实伤亡/计分；`ARTIFACT_DIR`保存来源/目标及HUD状态。脚本通过只读坐标辅助瞄准，不设置生命、伤害、位置或无敌；它不是玩家瞄准手感、AI强弱或交火性能的验收。

`src\weapon-simulation.js`按实体推进武器动作，不再在人物移动/镜头更新里推进拉栓，也不对当前载具重复更新装填。当前有效控制者的步枪只在装备时推进，收起／入座暂停；主游戏显式开启AI个人武器时钟，其他存活且未入座的士兵继续本人的拉栓／装填，AI空仓会自动排队装填。Y只转交控制，不重置任何武器；AI装填可在接管前自然完成，但不能被当成Y免费补弹。已启动的车载／班组支援武器装填仍独立完成，空支援武器不自动启动装填；全局暂停不推进任何武器。

机械动作只产生带士兵/武器ID的一次性反馈事件，由当前有效视角消费；其他AI或已收起步枪的声音不能串入新视角。换队时注销原单位支援武器登记，不让反复迫击炮出击积累无主武器，也不改写其已发射炮弹的原始来源。规则覆盖100次替换及30/60/144Hz；新增AI策略明确检查双方时钟、空仓装填、Y连续归属及阵亡／入座／全局暂停。有限备弹、AI空间机械音和第三人称装填动作仍未完成，相关G4/F11不因此勾选。

`src\construction.js`独立管理玩家工兵的蓝图归属、锁定位置、进度、取消及一次性完成结果，不读取相机、模型或DOM。候选点由士兵模拟朝向与共享地面高度计算，仍为前方5米；每步复用原位置/敌情/据点校验，保留6秒建造门槛及移动超过0.7米清进度、继续按住时在新候选位置重新起算的规则。蓝图绑定具体建造者，Y、收起工具、暂停、死亡和重开按原策略取消未完成任务，不让新队员继承进度；暂停不保留半成品供恢复后补齐。

HUD、预览颜色/位置只读取建造状态，完成/位置变化提示通过有限反馈事件消费。集结点登记保留原建造者ID，创建时核查其仍是本队活着的工兵；已建成集结点不因建造者换人或阵亡自动消失，仍受原耐久、损毁、敌情封锁和重部署规则控制。`test:browser`记录松手、Y、暂停取消以及正常完成/摧毁/部署，规则另验30/60/144Hz、位置锁定和单次完成。

集结点创建/替换/耐久转移由 `src\spawns.js` 的纯状态函数处理，每阵营仍最多一个，初始耐久120。重生点不再持有模型，`src\rally-renderer.js`按ID维护实际显示及射线目标；网格只标注`rallyId`，命中后回查登记状态，不把整个重生点对象塞进网格。损毁立即让部署校验失败，世界通知在表现层刷新提示/部署面板；重复命中已毁目标不重复触发损毁。替换、损毁、回大厅/重开清理旧显示和射线目标，不逐点销毁共享几何/材质。

规则与实际网格射线用例覆盖同阵营替换、两队隔离、已毁状态、渲染前即损毁及重开；`test:browser`检查普通步枪实际命中登记ID、耐久归零、对应视图移除和新局清理，`ARTIFACT_DIR`保留记录。当前弹道仍通过现有Three.js几何适配器求交，未改成独立物理引擎，也未增加集结点对地面移动/导航的阻挡规则。

迫击炮在飞弹由 `src\projectiles.js` 拥有起点、目标、当前位置、飞行时间和伤害，渲染网格只跟随模拟，不再由网格位置反推弹道。发射时冻结原单位/士兵/武器/载具/席位及个人或友军击倒归属；步枪、主炮、机炮和AI步枪的伤害也记录实际武器来源。换人、阵亡、撤出旧实体登记或同局重新部署不会改写已经发射的炮弹，暂停冻结其模拟；返回大厅或新局清理弹体、渲染对象及旧弹着记录。碰撞使用实际场景与载具几何，每弹只结算一次；在飞上限32、弹着历史32条，共享弹体几何和材质不逐弹销毁。

`npm.cmd run test:projectiles`通过正常迫击炮输入覆盖Y、暂停、真实近距爆炸伤亡、建筑碰撞及跨局清理；`ARTIFACT_DIR`可保存原射手/武器ID和实际弹着记录。此项未调整射程、弹速、伤害或装填数值，仍是既有弧线插值原型，不代表50–250米射程、真实弹道、弹种或全项目战斗表现分离已经完成。

### 手动画质与独立效果

大厅可选高/低画质，战斗中按Esc在暂停菜单调整同一档位，并独立开关动态阴影、距离雾、场景烟雾、画面颗粒、冷灰日光、枪口效果、枪口点光、弹着碎屑和受伤暗红边缘。高档像素比上限1.6、方向光阴影4096、场景烟雾上限30；低档分别为1.0、1024、10。实际像素比不会超过设备值，阴影尺寸不会超过GPU限制。低档仍使用同一套PBR/天空资源，不降低兵力或改变伤害、移动、弹药与据点规则，也不声称能保证所有PC达到60FPS。

独立开关跨档保留；设置仅当前页面有效，刷新后恢复高档。切换会释放旧阴影渲染目标，并同步窗口尺寸及必要的着色器状态；当前没有自动降级或后期管线，不显示假启用状态。`npm.cmd run test:quality` 检查真实画布/阴影尺寸、烟雾数量、各开关、重复切换后的纹理数量、720p大厅以及暂停时的战局连续性。

### 冷灰日光、枪口与基础弹着

`src\lighting.js` 提供既有HDR下的冷灰日光首版：降低暖色直射、增加中性补光，关闭选项可恢复原光照。没有替换天空资源，原HDR仍有蓝天；补光降低阴影对比不等于新增真实软阴影算法，整体现实感仍需人工复验。

`src\combat-effects.js` 复用实际步枪开火和命中事件：短时枪口焰、轻烟及3米范围/约0.05秒的局部点光；全局最多2盏点光且无点光阴影，低档禁用。使用真实命中位置、世界法线和材质标记生成石/土/木及通用碎屑，补齐现有铺装层的弹着射线，避免石板上冒出其下泥土的反馈。没有重做枪体、改射速或增加伤害。坦克/飞机/迫击炮的独立炮口表现、水面/全面材质、贴花与独立弹壳仍未完成。

渲染对象预分配，碎屑/烟尘/点光状态回收复用；上限分别96/18/2，低档32/6/0。暂停冻结效果，关闭模块或重开清理，碎屑沿用当前地面/桥梁支撑。受伤边缘只复用原反馈，关闭不会免伤。`npm.cmd run test:combat-effects` 核对实际石板/泥地弹着、GPU图像中的局部照明、暂停、关闭和低档预算，不把特效通过当作F1完成。

### 可选步枪PBR资源接口

`src\weapon-assets.js` 的 `RIFLE_PBR_ASSETS.wood/steel` 可配置本地 `public\assets` 下的贴图，浏览器路径采用 `/assets/...`。默认各通道为 `null`，保留程序化材质，不自动下载或要求外部服务。配置前应人工核对资源适用性与CC0许可证，并在对应项记录 `license: 'CC0-1.0'` 与 `source` 原始来源；配置声明本身不能代替授权审查。

可用通道为 `color`、`normal`、`roughness`、`metalness`：颜色使用sRGB，其他为线性数据；法线要求 `normalFormat: 'OpenGL'`，粗糙度读G、金属度读B，灰度图可直接使用。木托不允许配置金属度贴图；配置新木色时清除旧生成纹理的bump，避免错配。钢部件共享资源，前后视角仍使用同一枪体/材质。没有实现glTF模型替换或自动资源制作。

路径只接受本地 `/assets/`，非CC0声明、未知字段、错误法线方向或文件缺失会显示具体错误并阻止不完整资源出击，不静默回退。`npm.cmd run test:rifle-textures` 使用原始自制测试贴图检查真实加载、颜色空间、共用请求及失败提示；它不证明已制作出写实枪械表面。

### 普通步枪与封闭装甲：有限止错

敌军步枪兵识别封闭坦克后不再持续无效开枪，也不能靠普通步枪命中直接扣整车生命；会先寻找掩护、近距避让或保持警戒。伤害入口按人员当前座位归属检查武器/目标类别，下车成员恢复人员目标，不会因为玩家切回车内就让所有地面车组免疫轻武器。爆炸和当前其他武器保留原型伤害，**不是完整装甲穿深或已经拥有反坦克装备**。

本轮未新增火箭筒、反坦克手雷或炸药包，F13整体仍未完成。另修复同一次爆炸在自动切换受损车组后重复伤害同一车体的问题。`npm.cmd run test:armor` 通过正常坦克出击/接敌确认没有步枪火力和车体扣血，再用实际爆炸核对坦克仍可受损，并重新以步兵出击核对普通交战不受影响。

### 重生与工兵：当前明确规则

这些是为约220米宽的小地图采用的**原型参数，不是《Enlisted》的原始数值**：

- 中国步兵、迫击炮组从南侧步兵集结地或工兵集结点出击；坦克从装甲出发点出击。飞机从固定的南侧空中入场点进入，尚无机场起降。
- 日军首次部署和后续增援从北侧基地进入；日军工兵建成前线集结点后，后续增援优先使用它。重生点附近有对方地面部队时不能使用；飞机飞越不触发这一地面封锁条件。
- 每方最多保留一个工兵集结点，新建会替换旧点；建造耗时6秒、耐久120，敌军在18米内阻止建造与重生。建造点须在未占领据点边缘18米以外，周围留出2.8米生成空间。地形受阻会明确显示原因。
- 开局步兵一班的第一名队员为工兵。按2取出工具，右键启用集结点蓝图，绿色可建、红色不可建；按住左键完成建造，松手或明显移动会中止。当前不保留未完成蓝图，也没有工程材料消耗。
- 集结点可被双方枪炮破坏；敌方AI会射击发现的我方集结点。摧毁后提示、地图标记和部署可用性同步更新。己方集结点跨小队阵亡保留，新一局才清空。
- 五个独立班组是小队身份，不是五个兵种：步兵一班、步兵二班、迫击炮组、装甲车组、航空小队。换人不等于换队；步兵一班覆灭后，步兵二班仍是另一个合法选项。
- 当前仅禁止立即重选刚阵亡的班组，**未实现原作所有模式的小队轮换/冷却、团队载具数量限制、多人重生排队或工兵个人建造上限**。单人原型不伪造其他真人玩家的排队。

原10人班本轮各新增1名轻机枪手后，默认步兵开局为**110对110**：双方各10个实际单位，每个步兵单位11人，所有成员具有独立位置、生命、状态和登记出生来源。玩家控制其中一班，其余19个单位自主移动/交战；本班全灭后才换出击单位，其他友军不会随玩家重部署而重置。

单位从双方后方登记集结区安全展开，不在据点附近生成；同一自主单位须全灭、经过冷却且重生点可用才整队补充，工兵点可以影响后续入场。角色近远实例化、空间索引和AI/路径分时预算用于控制开销，远处降低几何细分和投影；近处己方枪体仍与第一人称同源。这不是已完成的人物骨骼动画、可靠大规模战术或真实历史编制。

`npm.cmd run test:population` 检查实际220名成员、20个单位、每班1名新增轻机枪手、出生净空/间隔、19个自主单位的移动及实战伤亡、Y与暂停、单载具替换和真实计数，`ARTIFACT_DIR` 可保存实机画面及观测数据。当前低画质无头Chrome观测不等于所有PC或高密度正面交火都保证60FPS；敌方真正夺取/反夺控制权仍待F29，不把进入据点防守当作已经实现。

标准步枪对普通人员采用50伤害/100HP，两次有效命中可致死；友敌AI使用相同的间隔和命中概率规则，10米内中心点/遮挡判定通过后不再额外随机判空枪，间隔仍尊重拉栓周期。建筑/集结点、飞机机体与爆炸伤害不是人物伤害，未随此项统一成50。当前仍没有完整部位、姿态命中区和实际散布模拟，不把这项参数止错说成射击系统已完全写实。

### G1可复现交火与性能采样

先启动开发服务器，再设置外部证据目录运行：

```powershell
$env:ARTIFACT_DIR = Join-Path $env:TEMP 'embers-g1'

```

默认顺序运行5v5和正常110对110各两次：1280×720、DPR=1、高画质、种子1938、初始预热3秒，正常人口按W前进到南街z≤42，观察真实AI开火后采样18秒。可通过 `BENCH_REPEATS`（1–5）、`BENCH_SECONDS`（5–60）、`BENCH_WARMUP`（1–15）、`BENCH_SEED`、`BENCH_SCENARIOS=duel,full`、`BENCH_QUALITY=high|low` 和 `GAME_URL` 明确改变配置。不同批次使用不同证据目录，避免覆盖。使用固定随机种子不等于固定帧调度；自然伤亡/整队增援仍启用，完整场景没有冻结为永远220名幸存者。

`BENCH_MIN_TIME`（0–180，默认0）可要求在至少指定模拟秒之后开始采样，仍须先观察到真实AI开火；记录同时包含采样前后尸体数。`BENCH_BASELINE_POSE`可指向先前采样保存的`sources.json`，对照其中的`src/nra-motion.js`、`src/entities.js`和`src/nra-force-renderer.js`：同一浏览器每轮交替旧／新、新／旧，其他模块及设置相同。仅开发请求被替换，不改磁盘源码或生产入口；保存两套源码、环境和每轮原始数据。对照期间不要修改源码或并行运行其他WebGL检查；不同浏览器版本的数据不能混作同环境对照。

2026-10-28人物热点批次只复用**完全相同本地姿态输入下的只读眼点**，移动、步态、举枪／装填意图、姿态或头颈目标变化立即失效；朝向及世界高度在返回后实时投影。不让远景选姿和枪口位置计算附带重算未使用的头颈投影，实际近景、人体和射击就绪检查仍保留完整姿态。两组100对100对照的姿态采样CPU包含耗时／模拟秒下降约23%／26%，但帧时间尾部仍不稳定，不代表稳定60FPS；具体数值和撤下的首版通用缓存见`TODO.md`。

该批生产版人物检查与高低画质检查已顺序通过，未放宽原断言。首轮页面加载超时、开发服务退出及原样重试的证据和未查明边界也记在`TODO.md`，不把未复现当作已确认根因。

开发专用URL `?benchmark=duel&seed=1938` 明确标记5v5诊断，`?benchmark=full&seed=1938`保留默认人口；`?benchmark=bridge&seed=1938`仅用于独立桥面几何检查。发布构建忽略这些参数，仍部署正常人数，不暴露写入生命、传送或无敌接口。`test:benchmark-config` 检查开发场景重开的出生记录与发布版220人边界。

### 活跃战局时钟与长帧追赶

`src\simulation-clock.js`替换原来每帧截断至50毫秒并丢弃余量的做法。正常帧保持实际帧间隔；长帧拆为每步最多50毫秒、每次绘制最多5步。**恢复帧另以本帧真实活跃间隔的1.1倍限制推进预算**，不再因为有积压就连续每帧推进250毫秒，造成玩家、AI和全战场突然快放。未处理时间继续保留、缓慢追赶，不丢弃事件或重置计时；相应代价是积压恢复需要更久。门、载具、武器、人员、AI、据点、炮弹和死亡接管使用同一批子步；每步消费反馈，画面最终绘制一次。积压达到0.25秒时HUD明确提示余量和追赶上限，开发逐帧记录包含补步数、积压和活跃总时长，不通过减兵或隐藏落后取得“正常”计时。

暂停结算其前的活跃边界并保留积压，不计入暂停期间墙钟，也不在暂停中推进；恢复后使用原控制归属并清旧按住输入。同局覆灭/重部署不重置战场时钟，回大厅或开新局显式清理旧时钟。短寿命世界枪口光、弹道线和爆炸以本批最终显示时刻出生，避免在首次绘制前被后续补步耗尽；伤害/击倒来源和事件时间仍为真实模拟时刻，个人红边与命中标记仍按原模拟规则。

`npm.cmd run test:clock`使用明确标注的无敌军桥面诊断，通过普通输入射击和650毫秒主线程阻塞验证5步上限、积压提示、随后追回完整时间、枪口光首次可见、保留未处理积压的暂停/恢复及跨局清理；没有更改生命/位置或提供可写测试接口。`node scripts\movement-speed-smoke.mjs`另在正常战场通过真实输入和前台阻塞检查追赶预算及实际位移，不仅断言标称跑速。该诊断不算持续200人性能证据。当前是有界可变子步，不是完整固定tick/渲染插值或历史输入回放；严重持续过载仍可能累积落后，短暂个人反馈也仍需低帧率人工复验，不能把不丢时间说成已消除长帧或达到稳定60FPS。

浏览器冒烟检查默认通过本机已安装的 Google Chrome 无头运行，需要先启动开发服务器；可用 `GAME_URL` 指定地址、`ARTIFACT_DIR` 指定截图目录。它检查工兵工具、建造中断/完成/摧毁、重生来源、敌军工兵前线点及增援、射击和小队操作、阵亡后选择与确认、选择期间战斗继续、载具及重新开局；不评估美术质量或历史准确性。
