### 本地玩法改版

默认台儿庄“城寨攻防” → 小队卡片 → 点击战术地图出生标记 → 确认出击。首次与整队阵亡共用同一部署面板。“街巷争夺”从大厅隐藏，普通旧链接自动选择“城寨攻防”；原资源和诊断用布局不删除。只开放步兵／装甲／航空三类；战役确认只下载轻量布局JSON，角色、枪械和三维战场在确认出击后加载，不承诺固定几秒或只下载玩家一队。`npm run dev/build`先按源码生成战术地图及其哈希目录；Windows监听排除资源审计临时目录，避免测试产生的文件锁中止预览。

大厅仅保留一处战役选择：右侧阶段下拉框。左侧保留游戏标题，移除中国位置图、宣传句、重复战役按钮和部署示意图，改为用户提供的23张影像照片墙；操作、声音和版本信息统一放入默认折叠的“设置”。首次选队和阵亡部署不显示暂停设置入口。

加载页显示“1931-1945 山河”及真实阶段提示，与大厅共用23张用户提供的照片／绘画，按用户最终选择改为一条横向照片墙，以72像素／秒从右向左连续滚动，不像PPT逐张切换。每张图片独立一格，高度限制在视口44%／420像素以内，宽度随原比例变化，竖幅人物不再放大到超出窗口。两份同序列无缝衔接，副本不重复向屏幕阅读器播报；可暂停滚动，减弱动画偏好默认静止。大厅照片墙占满战役面板左侧的可用空间，仍保留操作间距。页面隐藏、切后台或进入战场时暂停对应照片墙，不延长实际加载时间。素材原始PNG及来源／哈希保存在`public\assets\loading`；原作者与公开再分发许可尚未核实，不能标记CC0，公开发布前须确认。Windows预览排除该目录PNG文件的监听，保留清单更新监听，避免新增图片时的EBUSY锁退出。

工兵建造重生点已从实际游戏接线移除，双方AI不再建造／攻击集结点。步兵可从已占据点后方约50米的安全位置重生，受阻时左右前后找安全空间；近于初始基地的重复位置不提供，据点失守即时撤销。新队出击时重新检查安全与整队空间；坦克只在初始装甲点，航空只在空中入口。

友军飞机增加翼肋、铰链、撑索、座舱束带、仪表和开中心孔的瞄具；日军使用独立的[Ki-10九五式战斗机](https://en.wikipedia.org/wiki/Kawasaki_Ki-10)方向程序模型，并真实巡航、攻击、拉起和返转，不是装饰飞过。日军仍为10单位／96人：8支步兵、1支四人坦克与1名飞行员，其中一个步兵单位补足原坦克减少的3名人员；玩家选择不同类型时友军相邻步兵单位补足110人。不是历史编制复原，空战模型仍为原型。

日军转向按航向误差渐减，倾斜采用有界平滑过渡，边缘返转有滞回，避免无受击时机翼左右反跳。飞机模型按航向、俯仰、本机横滚顺序显示，使倾斜不改变机头与实际飞行方向的对应关系。

玩家驾驶时鼠标只设定期望方向，由飞机逐步跟随，不会瞬间转头；W/S俯仰、A/D滚转、Q/E方向舵，Shift/Ctrl或滚轮调油门，按住C环顾、右键放大、左键射击。HUD显示空速、离地高度、油门、期望方向及失速提示。飞机的无损飞行区扩大到`x/z ∈ [-600, 600]`；越界仍保留预警、8秒宽限和逐渐损伤，地面战区边界不变。暂停时操作、声音和画质设置默认收起，点击“设置”才展开。

我军I-15bis继续增加发动机九缸冷却鳍、48段机身曲面，以及座舱机鼻／下翼、侧轨、面板紧固件和弧形风挡。该机型是1937年改进的双翼机，中国当时使用过I-15／I-15bis系列，可参考[Military Aviation Museum介绍](https://www.militaryaviationmuseum.org/aircraft/polikarpov-i-15bis/)；日军Ki-10在1935年服役，双翼结构符合机型本身。两者在本项目的台儿庄配属仍是玩法原型，不声称已确认当地具体单位、机号或历史空战。

日军地面攻击保持同一有效目标，优先前方射界，按接近、瞄准扫射、近距／低空拉起和返转执行；开火检查真实目标方向而非被限幅的俯仰指令。击毁后保留最后速度并受重力坠落，接触地面／建筑才停下，不在空中冻结。补充飞机在注册到单位后立即创建／同步碰撞显示，避免重生与同一步手雷碰撞查询之间缺少模型。

AI合并重复／矛盾表现规则：有可用射界时保持当前姿态，不强制每枪换姿；只有持续受压、没有掩护且允许移动时才低频换位，无安全落点或压制解除则取消，不无期限停火等待。移除旧工兵／集结点分支及硬编码建造位置；遮挡、友军安全、真实转向、库存、死亡与画外模拟照常保留。

## 当前人物与双方外观

整队阵亡后的部署流程为**选择小队卡片 → 点击战术地图上的己方出生标记 → 确认出击**，不是下拉菜单选择位置。标记显示名称、距最近据点距离、可用／受阻和选中状态。允许重新选择同类型新小队；步兵可用已占据点后方安全位置，坦克仅初始装甲点，飞机仅空中入口。参考[Enlisted官方重生界面距离提示说明](https://enlisted.net/en/news/show/616-making-enlisted-a-better-place-52-en/)，但不恢复工兵建造或原作养成规则。
当前投掷装备固定分槽：**5手榴弹，6定时炸药包**（G只兼容选择手雷）。再按同一数字键不会循环种类；该物品用完时明确提示，不自动换成另一种。两者各自显示库存，操作仍为左键准备、松开投掷；6不是遥控TNT起爆器。

栓动步枪最后一发打完后自动排队装填：完成本次拉栓，再执行与R键相同的换弹流程。装填结束才补足弹药，重复R不重置进度；仍有弹药时可按R主动补弹。

迫击炮架设瞄准时显示A/B/C方位标记；中心方向对到据点时显示其名称与实际水平距离，并单独显示当前设置射程，便于鼠标前后校准。射程外标记不会隐藏，也不会自动改射程或保证命中。

迫击炮发射采用[Thimras的CC0 Cannon fire录音](https://opengameart.org/content/cannon-fire)裁切／滤波的1.1秒短声，通过枪炮音量组播放；这是炮声改编，不是历史迫击炮录音。首次点击画面恢复浏览器音效。炮弹弹着复用炸药包爆炸流程：人员峰值伤害240、半径9米，载具使用同一4米／720峰值反装甲曲线，遮挡、友军保护和原开火者归属保持一致；爆炸烟尘／碎片样式也一致，不只是扩大视觉火球。

本地改版中的步兵班1号为**迫击炮手**，保留步枪和手榴弹。成员栏显示“迫”，当前角色与装备栏分别显示“迫击炮手”和“2 炮”；按2选择炮，站定后**左键架设**，鼠标左右调方向、上下调节50–250米射程，架设后再次左键发射并自动装填，右键退出瞄准／收起，1切回步枪。架设输入本身不发射、不耗弹；架设中／架设后不能移动，炮弹按本人库存与冷却保存，换人不补弹。地图外目标明确禁止发射，不把它夹到地图边缘制造假命中。操作流程参考[Quadro的Enlisted迫击炮教程](https://www.youtube.com/watch?v=5C4zSGRf1ro)及用户明确的左键架设要求（非最新版客户端默认键位认证），50–250米是用户指定的本项目射程。

迫击炮模型具有开口炮管、炮口内壁、底板、双脚架、横撑、调整螺杆／摇柄与瞄具；架设时在实际炮位地面显示，不再把两根圆柱悬在镜头前。玩家蹲姿操作，炮弹从可见炮口发出；模型为原创轻型迫击炮原型，不声称实物测绘。

近景原生角色在同一模拟步完成AI移动／转向后再更新动作，站定转身采用支撑脚与低摆动脚，重心最多降低4.5厘米以避免双膝绷直旋转；原骨长和实际位移不变。这是局部动作修订，仍需玩家实机检查近景衔接，不把远景修订或数值检查视为整套人体动作验收。

交火时沙袋已有实际可选掩体槽位，友军优先附近15米内有遮挡、射界及路线的掩体，不因位置略偏离进攻目标就忽略它。中距离开阔地射击优先有射界的蹲／跪／卧姿；近距离遭遇、移动还击或只有站姿有射界时仍可站射。无实际威胁的跟随警戒不再全员长期举枪，不把“必须找到掩体”设为停火条件。

### 我军大刀与数字装备槽雏形

第一人称大刀收势减少向身体内侧翻转，刀身结束方向更偏向前方；手腕、刀柄和肘部仍共用原连续解算，不改原骨长或第三人称刀法。肩根裁边仍是未修复项，不把这一轮挥刀观感调整当作衣袖修复。

### 双方战场喊话与必播事件

游戏已内置 **266 段 Azure AI Speech 合成男声录音：262 段 MP3＋4 段已通过试听的中文延音 WAV**。国军使用普通话云健／云希／云枫，日军使用日语 Keita／Daichi／Naoki。常规台词每方 26 句，我方另有 36 句钟点方向报点，每句均有 3 种声音；云健／云枫的“冲啊！跟我上！”另各有短／长两种演绎，代替这两条旧MP3。台词为原创虚构对话，不是历史录音、真人声音克隆或方言／历史口令考据；中文带受支持的愤怒语气，日语采用不同男声及语速／音高调整，**不保证达到真人战场嘶喊的表演效果**。台词与日语释义见 `src\battle-voice-lines.js`，音频与生成参数、校验和、使用条款出处见 `public\assets\audio\battle-voices\source.json`。生成语音受 Azure 服务协议约束，不标记为 CC0。

本次只采用用户已认可的中文A／云健、C／云枫这句推进喊话，使用试听时的`angry`、强度1.8、语速+12%、音高+2%、响亮音量与80ms句间停顿；Azure字词边界定位“啊”，再局部保音高／共振峰延长至约0.4／0.7秒。其他字词复用同次试听合成片段，仅有整体均衡音量和PCM量化差异；不是对旧游戏MP3直接变速。抽中这句后短／长按3:1选声，台词本身仍与另外两句推进喊话等概率，两种长度共用防重复规则；不增加触发次数或改变冷却。**全部日语对白与其余中文对白原样保留**，未通过试听的日语V5/V6不接入游戏，具体尝试与否决经验保存在`TODO.md`。

附近存活步兵在推进、接敌、受压、装填、躲避手榴弹时随机喊话，按士兵固定分配音色，随位置更新左右声像及距离衰减，55 米外不播放；全局间隔 5–8 秒、阵营冷却 9 秒、个人冷却 28 秒，避免全军齐喊。车内成员、阵亡士兵和玩家本人不参与环境随机喊话。

另有 **30 段 CC0 真人无词喊叫／闷哼**，来自 HaelDB 的 [Male Grunt/Yelling sounds](https://opengameart.org/content/male-gruntyelling-sounds)，双方共用，不冒充中文／日文母语表演。保留原有三个音色、每类两种的 18 段短反应，并接入用户试听后保留的 **12 段额外受击喊叫**，编号对应试听页 01–12。新增片段是双方及各音色共用的独立表演池：**08–12 每条权重为 3，01–07 每条为 1**；受击选声同时保留当前士兵音色的两段原短哼，各权重 1，并排除上一段受击录音以免紧接着重复。权重只改变选声比例，不增加受击触发概率或喊叫总次数；其余语音、日语对白与音色不变。

真实受击仍可立即概率触发反应，较长的新录音保留完整尾音、上限 4.5 秒；不会因为普通行军或单纯低血量反复惨叫。近敌突击及受压状态变化继续使用原有短喊。单独通道最多一声、全局间隔至少 1.5 秒、个人冷却 8 秒、35 米外不播放，隔墙减弱并低通；即使长喊尚未结束，也立刻给命令／公告／报点让路，丢弃的反应不排队补播。暂停、战果及重开停止旧声音。运行时为 `src\battle-reactions.js`，共用选段及权重目录为 `src\battle-reaction-clips.js`；原始来源、选段校验和及处理信息见 `public\assets\audio\battle-reactions\source.json`。用户的选声偏好不代表各片段的疼痛／恐惧／绝望分类或历史真实性已经独立验收。

**枪声按原始射击事件选择，不靠背景循环模拟射速**：我方普通／狙击步枪分别使用用户提供的两份生成音频，详见下述“当前步枪声音”；日军步枪／栓动狙击枪使用用户指定的 `single-gunshot-54-40780.mp3`，保留约三秒完整枪声尾音，坦克机枪不套用该录音。其原作者 morganpurkis 在 [Freesound](https://freesound.org/people/morganpurkis/sounds/391847/) 提供 CC0，来源记录包含用户 MP3 与原作者预览的波形对照。双方 ZB-26／十一年式轻机枪使用用户指定 `foisal72-gun-fire-346766.mp3` 的三个 **95 毫秒单发片段**，排除原录音的连发间歇，每次真实开火只播放一段，按武器现有 0.12 秒周期发声，松开扳机不继续循环，也不变速整段连发；同轴机枪共用单发片段但按自身0.1秒周期发声。两类素材分别记录于 `public\assets\audio\enemy-rifle` 和 `public\assets\audio\machine-gun`。**机枪素材不是 CC0：索引标识为 Pixabay Content License，但源站与许可页面直接请求返回 403，公开发布前仍须补齐独立授权核查；不能作为独立音效包再分发。** 这些选用不代表历史枪型真实性或听感已验收。

重新处理需要 FFmpeg；人声压缩包读取另需 Python。以下脚本只接受已记录 SHA-256 的源文件，下载包和原始长录音不放入游戏资源：

**18 米内的友军步兵会主动提醒狙击手、机枪手和敌军坦克**，例如“三点钟方向，敌方狙击手！”“十点钟方向，敌方机枪手！”“前方发现敌军坦克！”。覆盖全部 12 个钟点方向，以**开口时玩家相机的水平朝向**为准：12 点正前、3 点右侧、6 点后方、9 点左侧，而非队友自己的朝向或固定世界坐标；报点后的转头不改写已经说出口的方向。队友必须有 1.2 秒内的真实目视识别，且开口前再次通过原有视线／遮挡检查；仅听到枪声、旧记忆、阵亡目标、远处队友都不会触发角色报点，不给玩家隔墙透视。坦克依据实际乘车目标的封闭装甲身份识别，按整辆车去重，不能把四名车组说成四辆坦克。

**有效 X 命令每次必播，不受随机喊话冷却限制**：短按依原规则命令进攻瞄准的据点或移动并守住标记位置，长按取消命令并跟随；语音与实际命令一致。连续命令立即替换前一条指挥喊话，不排成长队。出击、开始占领、首次据点争夺、未夺取据点的占领进度清零、拿下／重新夺回据点、我方据点失去控制、我方集结点被毁、胜利、失败、平局都有事件语音；事件公告按顺序播放，不被环境随机喊话挤掉，据点公告和最终战果分别保留。暂停停止播放，恢复后重播未完成的公告，回大厅／新局清空旧语音。

模型为本项目原创程序化几何，不提取或复制参考游戏的模型／贴图：三色迷彩、分段倾斜车首、铆钉、短炮与炮盾、偏置炮塔和指挥塔、环形天线、翼子板、发动机百叶、排气罩、车灯、牵引环及车体／炮塔后向机枪外形。车轮和履带按实际行驶距离运动，炮塔和炮管分别跟随模拟角度；静态部分按材质合批，几何与材质共享。不是扫描资产或照片级美术，车内未建模。

四人车组和主炮有独立实体、席位、生命、武器归属与装填时钟。AI沿按车体净空建立的地面导航推进，按完整转向包络预留车辆间距；路线额外保留10厘米余量，并对齐行驶方向再走，避免在桥头等障碍的精确切线上因微小偏差卡住。静止车辆及残骸始终作为障碍；行驶中的坦克只参与附近交通规划，若绕行代价过大则在真实碰撞约束下排队，不把几十米外的前车当成永久封路。窄路汇入时让先到者优先，后车可短距离倒车腾出转弯空间，路通后继续推进。动态车辆移动后局部刷新路线，不穿墙或传送。

**车体导航始终以当前据点为目标，炮塔独立跟踪敌人**，发现敌人不会改走追敌路线，也不会因进入30米交战距离就长期停在后方。主炮仅在有弹、射界安全且接近瞄准完成时短暂停车，单次瞄准停车最多1.2秒，两次停车开始至少间隔4秒，射出即结束停车，装填及射界被己方步兵挡住时继续推进。两车分配据点中心左右各4.5米的独立驻守位置，推进到各自位置1.25米内才驻守；间距包含停车误差及转向净空，不在桥上离中心6米处提前横向封堵后车。驻守时车体转向可见敌人，让前向机枪有机会进入射界，而不是始终侧对来敌；途中仍按据点路线推进，不为追敌改道。当前据点被攻占后立即切换下一据点，诊断快照公开目标据点、导航终点、距据点中心的直线距离及交通规划状态，不能用履带里程冒充已经抵达。炮弹沿用即时射线和有遮挡的范围爆炸，不是新增真实弹道。生命280、移速4.2米／秒、5.5秒装填、125爆炸伤害、6米范围、95米射程均为**游戏调校，不是历史射速或穿深模拟**。城市窄路仍会合法绕行，不通过加速、传送或让远处步兵原地等车来保证坦克永远最靠前。封闭装甲规则不变：步枪与手榴弹不能直接损坏它，坦克炮／迫击炮／航空及范围爆炸仍可损坏；未新增反坦克步枪、穿甲弹或弱点系统。

**车体前向机枪与炮塔后向机枪均可实射**，不是把后向枪改成虚构的前向同轴机枪。[九七式车载机枪资料](https://en.wikipedia.org/wiki/Type_97_heavy_tank_machine_gun)记录7.7毫米、20发可拆弹匣及500发／分循环射速。两枪各有独立武器归属、弹匣和时钟：每次最多5发短点射，射后至少冷却1.6秒，20发打空后换弹3.8秒；与主炮装填互不补弹、互不重置。车体枪由存活的车体机枪手操作，炮塔后向枪由存活的车长操作；缺少对应车组或车体被毁即停火，同一名车组不能同一刻兼射主炮和机枪。每挺枪在自身有限射界内跟踪目标，模型枪口与射线一致，有散布、曳光、枪口火光和现有临时小武器枪声；实际射线命中才造成伤害，墙体及其他车辆会挡弹，己方步兵遮挡时停射，不向封闭装甲或飞机扫射。55米射程、35点基础伤害、点射／冷却／换弹时间和射界均为游戏调校；冷却是点射间歇的抽象，未实现温度曲线、换枪管、卡壳或有限总备弹，枪声也不是该型号的历史录音。暂停冻结两枪的射击、冷却和换弹，重开清空旧武器。

被毁后杀死剩余车组，保留焦黑残骸及碰撞；车组清理后残骸按现有30秒策略退场。**坦克小队全灭后在下一次兵力刷新（最多约1秒模拟时间）补充**，不等待步兵的17秒冷却；每个小队只补充自己的下一辆车，不复制仍有存活车组的小队，目标始终为2个作战坦克小队。仅从各自北侧装甲出发点补充；若敌军、残骸或障碍堵住出发点则记录原因并每2秒重试，不在步兵集结点刷车或穿过障碍强行维持数字。旧残骸不计作作战坦克，因此短时可见残骸加2辆活车。暂停冻结移动、履带、装填与补充，回大厅／新局清空旧实体及显示。

**步坦协同采用局部车后掩护，不是远距离追车**：自主步兵只考虑16米内同阵营的存活坦克，车后位置必须在8米局部移动范围内，不能让距离当前推进目标的距离增加超过4米；从掩护点到威胁的方向还须真正穿过车体，不能把侧面／背面来敌算作受掩护。按实际车体朝向安排12个分散车后位置，排除被占用、不可直达或受阻的位置；坦克移动时更新位置，交火时沿用停稳、抬枪及实际射界检查，在侧方探出射击，车体仍会挡住步枪子弹。坦克过远、被毁、掉头或局部位置不可达时释放跟随，继续原有推进／冲锋或交火决策，不会后撤几十至几百米去找车。手动控制及玩家本班的明确命令不被自动协同覆盖，手榴弹避险优先。

### 狙击手与开镜操作

每个步兵班保持 **11人**：1名工兵、8名步枪手、1名狙击手、1名轻机枪手。按用户选择，将原第10号步枪手改为狙击手，不额外增员；正常战局国军10个步兵班有10名狙击手，日军8个步兵班有8名狙击手，另有上节2个四人坦克小队，双方总人数分别为110及96人。Y可切换至标有“狙”的第10号队员，补充与重新出击使用同一配装，迫击炮／装甲／航空编制不变。

### 倒地与尸体保留

玩家本人步枪在上一轮提高3dB后再提高2dB，相对最初混音共提高5dB（线性增益约1.778倍），不提高共享总线或改变机械声／脚步音量；不是对真实危险枪声响度的复刻。`npm.cmd run test:rifle-audio`检查实际玩家／NPC播放与明确降级；开发服务器上运行`node scripts\rifle-mix-smoke.mjs`另以真实录音验证各距离浏览器实际输出、本人额外2dB、左右声像和九声部同步峰值，后者是合成极限检查而非战斗性能／人工听感验收。`GAME_URL`指定开发服务器，`ARTIFACT_DIR`保存观测。

`/audio-study/`是仅供本地开发试听的新音源对比页：当前片段、Arisaka近距和莫辛近距，各0.6秒，恒定增益匹配RMS电平，统一试听音量，不额外压缩或变调。新候选来自[The Free Firearm Sound Library](https://opengameart.org/content/the-free-firearm-sound-library)，明确CC0、可免费商用；来源、原／处理后SHA256和限制在`audio-study\assets`。**用户试听后认为B／C不如当前A，两份新候选未采纳，暂保留现有音源；这不是对A音色的最终认可。**Arisaka源库标注.30-06，并非已核实的原装三八式；莫辛也不是中正式。两者都是枪手前方而非射手耳位，处理后源文件存在满刻度样本；RMS相等不保证听感等响。此页不加载游戏，也未替换正式音源，Vite默认生产入口不打包该目录。使用`node scripts\prepare-rifle-candidates.mjs <解包目录>`从已校验原件重新生成，`node scripts\rifle-candidates-smoke.mjs`检查浏览器播放／解码与明确失败；服务器及观测目录同样用`GAME_URL`／`ARTIFACT_DIR`指定。

**旧 A/B/C/D 试听轮次已暂停：这些候选均未通过音色验收。**A太闷、缺少利落的爆裂感；B／C不如A；D的均衡处理也未获认可。本轮我方普通／狙击步枪已另外指定上面的两份生成音频，日军步枪与双方轻机枪也按另行指示替换；旧试听页仅保留记录，不代表新素材已获最终音色验收。D曾作70Hz高通、350Hz削减3dB、3.2kHz提升3dB并匹配电平，不增加压缩或变调，也不会修复原录音削波或确认未知枪型；未接入游戏，不能把频段能量变化当作人工音色认可。

### 步枪机械操作声音

控制士兵的步枪已接入解锁、后拉枪栓、装填、闭锁四份CC0拟音，WAV共51,776字节；开一枪听拉栓，按R听装填即可试听，不需打开独立素材。只消费原`weapon.mechanical`动作事件，不在扣扳机时提前播放整套声音，也不改变弹药、射速或动作时序。每绘制帧最多启动3个、同时最多4个声部；换人、死亡、暂停、收起步枪及入座停止原队员尾音，新局清理事件序号。只播放当前士兵和当前武器的个人声，不把友／敌AI机械事件当作近耳声。

来源为[LFA的混合机械录音](https://opengameart.org/content/equipment-clicks-iii)及[BMacZero的装填音效](https://opengameart.org/content/gun-reload-sound-effects)，均明确CC0，可公开仓库及浏览器分发。LFA原录音混有步枪、订书机和卷尺，单个片段物体未经核实；这不是已验证的历史步枪实录，也不是弹壳落地声。来源、原始哈希和处理记录在`public\assets\audio\rifle-mechanical`；听感与战场混音仍待人工复验。任一文件加载或解码失败时控制台、HUD及出击提示明确告知，并使用原合成机械声，不关闭其他枪声和脚步。`GAME_URL`指定开发服务器后运行`node scripts\rifle-mechanical-game-smoke.mjs`检查正式游戏播放、暂停／换人／切工具／车组切换、新局及HTTP／解码失败路径；`ARTIFACT_DIR`可保存观测。

### 地表脚步录音

控制士兵的站立／蹲行接触及落地使用已在库的 [Kenney Impact Sounds](https://kenney.nl/assets/impact-sounds) CC0录音：石地用 `concrete.ogg`，木地板用 `wood.ogg`，泥地暂用 `grass.ogg`。三份原文件共20,047字节，复用诊断页已有文件，不新增下载副本。浏览器内按24kHz解码、混为单声道，从原接触起点保留最多0.11／0.14／0.16秒，去直流、限制峰值并淡入淡出，避免长尾叠响；原文件与哈希不变，处理及来源记录在 `public\assets\audio\kenney-impact\source.json`。

声音继续消费实际位移产生的 `movement.footstep`，使用事件捕获的原士兵、地表、姿态和速度，不按墙钟另造落脚、不反读渲染骨骼，也不调整移动规则。速度、蹲行和落地只改变接触音量／滤波，轻微音高变化不改变落脚时序。每绘制帧最多启动2个接触音、同时最多4个，暂停、换人、入座及新局会停止旧接触尾音；追赶积压时可能舍弃超预算声音，而非密集补播。

这是每种地表一份录音的基础辨识改善，**不是完整军靴拟音或听感已验收**；泥地的草地代用品仍需替换，匍匐保留原合成摩擦声，友／敌AI脚步尚未接入同样的完整事件路径。加载／解码失败时控制台、HUD和出击提示明确告知，保留原合成脚步，不影响步枪录音。`npm.cmd run test:footstep-audio`需要开发服务器，`GAME_URL`可指定地址，`ARTIFACT_DIR`可保存观测与截图；三种地表路线是明确标注的无敌军几何诊断，另查正常100对100启动和实际枪声，不当作规模性能或人工听感验收。

## Cloudflare 部署

项目使用 Cloudflare Workers 静态资源托管。根目录的 `wrangler.toml` 明确指定上传 `dist`，无需 Worker 入口代码或 `@cloudflare/vite-plugin`，也不改变本地 Vite 启动和预览方式。只发布构建产物，不上传 `src`、测试或 `references`；`public\assets` 会由 Vite 复制到 `dist\assets`。

在 Cloudflare 的 Workers Git 集成中连接本仓库，根目录使用仓库根目录，并配置：

| 设置 | 值 |
| --- | --- |
| 构建命令 | `npm run build` |
| 部署命令 | `npx wrangler deploy` |
| Worker 名称 | `1931-1945`，与 `wrangler.toml` 一致 |
| 生产分支 | `main` |

确保 Cloudflare 构建的分支已包含 `wrangler.toml`。如果使用其他 Worker 名称，同时修改该配置中的 `name`。不要在构建时自动接入 Vite 插件：缺少明确的 Wrangler 配置时，自动接入可能因现有 Vite 配置没有 `plugins` 数组而失败。

也可以在本机完成 Cloudflare 登录后发布：

```powershell

```

仅检查打包和部署配置、不上传资源时，使用 `npx.cmd wrangler deploy --dry-run`（先运行构建）。部署在域名根目录，以保持 `/assets/...` 路径有效；未配置 SPA 回退，缺失资源返回404。发布后仍是桌面 WebGL 单人游戏，不会新增后端、多人联机或跨刷新存档。

## 原型玩法概览

玩家只选择中国阵营，开局直接部署步兵、坦克、迫击炮或飞机；没有解锁和养成。步兵由玩家接管本班存活成员，整班覆灭后才可选择其他班。台儿庄主题战场采用A/B/C三点争夺，双方AI会移动、交火、占点／反夺；工兵可建造集结点。移动、换人、重生及单局规模见下文“当前作战规模”和“操作”；声音、人物、载具和场景细节在各专题说明，不在这里重复列参数。

战斗循环浏览器检查入口为`npm.cmd run test:assault`；该正式人数回归覆盖双方110／96、AI推进／反夺和整队增援，不等于完整战术自然度或性能验收。`GAME_URL`指定开发服务器，`ARTIFACT_DIR`保存观测。

### 负重移动：当前调试规则

这些是本项目的米制调试值，不是《Enlisted》实测参数。WASD默认慢跑，按住C慢走；站立向前移动时Shift冲刺，举枪时Shift仍为屏息。步兵速度为慢走1.75、慢跑3.15、冲刺4.8米/秒；迫击炮搬运分别为1.4、2.45、3.7米/秒。倒退更慢，蹲、卧、举枪另有速度限制。

移动有加速、制动与转向惯性。脚步、镜头和枪身基于碰撞后的实际位移驱动；顶墙不持续踏步，松键后有短暂制动。步频约为慢走2.3、慢跑3、冲刺3.6次触地/秒。枪身随步态、转向和冲刺产生滞后；冲刺后举枪需要约0.45秒恢复，其间不能立即开火。

冲刺持续消耗体力，耗尽后暂时不能冲刺，恢复到35%才解除疲劳限制。每个队员独立保留体力；非控制队员缓慢恢复，Y来回切换不会补满原队员体力。跳跃也需体力。控制士兵接触声已按石板／木地板／泥地切换CC0录音，泥地为草地代用品、匍匐仍合成，详见“地表脚步录音”；友军已有基础骨骼低步态，完整装填、受击等动作仍未完成。

镜头步态的标准／减弱／关闭可在大厅操作设置或Esc暂停设置调整，不再占用B键；B只用于架枪。该设置只减弱镜头步态，不取消必要的瞄准、后坐力与枪械动作，也不改变速度或体力；与画质、各项特效和灵敏度一起保存在当前站点的浏览器本地存储，刷新／返回大厅后保留，不保存战局。

### 操作设置与本地记忆

大厅折叠的“操作设置”和Esc暂停菜单可分别调普通视角、瞄准灵敏度（25%–300%，每档5%）；两者是独立倍率，不相乘。100%保持原手感：普通视角0.0022弧度／输入像素，举枪瞄准保留0.6倍、狙击镜保留0.22倍原降速，再乘瞄准倍率；不是把镜内外速度强制设成相同。设置不改变射速、伤害或模拟时间。“恢复操作默认值”只恢复两种灵敏度与镜头步态，不重置画质。

### B键依托架枪与空格翻越

玩法参考已核对：Enlisted可在沙袋、墙顶／窗台等表面支撑枪械，降低后坐力；参见[官方论坛玩家对架枪位置及稳定性的讨论](https://forum.enlisted.net/t/any-tips-for-mounting-weapons/25080)。这是玩家经验，不是开发者公布的精确公式。[PC操作表](https://www.magicgameworld.com/enlisted-pc-keyboard-controls-and-key-bindings-guide/)列出Space跳跃、V标记敌人，论坛常见架枪键为B或玩家自行改键；**本项目按用户2026-10-29确认使用B架枪，V不绑定架枪**。旧镜头步态快捷键B取消，调节保留在Esc暂停设置；不能让一次B同时触发两项功能。未复制原作代码、动画或资源。

步兵持步枪、狙击枪或轻机枪站定后，看向距离前护木合适的沙袋顶、矮墙或窗台，按B进入支撑，再按B解除。检测实际场景表面及朝上法线，不对任意附近墙体发放加成；高度不合适时提示调整站／蹲／卧姿态。约0.2秒进入支撑，第一人称视角和枪身平滑贴近支点；水平射界约左右36度、俯仰约上下20度。完全支撑时瞄准摆动约为原来的20%，步枪后坐力约30%、机枪约20%，均为游戏调校，不是历史参数或Enlisted实测值。按实际瞄准方向和实体枪口结算射击，原有枪口受阻与掩体挡弹检查保留。移动、侧身、改变姿态、换装备、装填、跳跃、切人、暂停、阵亡或支撑失效时解除，需要重新按B架枪；不自动展开脚架，也没有新增第三人称双手贴合支撑点的IK。

站立时Space优先检查前方约1米内、高约0.4–1.35米且厚度不超过1.4米的低障碍，可用则执行约0.85秒的抬身、越过、落地；否则普通跳跃，蹲卧时先起身。普通跳跃消耗8%体力，翻越消耗14%。翻越检查整段身体轨迹、头顶净空、另一侧落点和落差，不能穿过高墙、窄角或窗楣，动态障碍挡路时停止前进并落向实际支撑面。翻越期间收枪，不能射击、投掷或交互；暂停冻结动作。跳跃和翻越改变实际士兵位置，人物显示、受击代理和枪口跟随，不再只抬高相机；Y接管不会让原成员悬空，他会沿自己的动作时钟落地。尚无专门的第三人称翻墙骨骼动画、高墙攀爬、翻窗或AI主动翻越，也未新增坠落伤害。

### 第一人称步枪：当前实现与限制

本轮原创样枪采用中正式/Type 24风格，以帝国战争博物馆[1936年巩县藏品 FIR 7135](https://www.iwm.org.uk/collections/item/object/30029566)记载的全长111厘米、枪管59厘米作为比例参照；[1944年藏品 FIR 8276](https://www.iwm.org.uk/collections/item/object/30032572)记载110/60厘米，不能把不同藏品数值混为一件实物。馆藏文字确认其与Mauser Standard Modell的关系，但页面没有可公开查看的实物图像；**尚未完成外观逐项实物对照，也没有确认当前台儿庄小队的具体配枪**。因此界面标为“比例样枪”，不是精确历史资产。

第一人称与己方第三人称使用相同的枪体/枪栓几何与材质；第一人称另外添加手部及动作层，第三人称仍是简化持枪姿势。新模型有连续变化截面的木托、倒角机匣、开口机匣/枪栓、枪管箍、V形照门、准星、护圈与背带，以及原创生成的胡桃木纹、发蓝钢材、布料表面。静态部分按材质合批并共享缓存。肩—肘—腕使用两段程序化求解，上臂约35厘米、前臂约34厘米，袖子有肘部、收口和体积，不再用一根过长直筒连到枪上。手指仍简化，**不是完成的蒙皮人物、专业烘焙资产或生产级LOD管线**，整体观感仍待复验。

射击后有0.65秒开锁、后拉、复进与闭锁动作；未闭锁不能再次发射。R可在拉栓时排队装填，随后执行2.7秒装填；弹仓空时展示五发桥夹，部分弹仓展示逐发补充。弹药仅在动作结束后一次性提交，尚非逐发中断/膛内弹完整模拟。暂停冻结动作；当前控制者收起步枪／入座时暂停个人动作。Y交给AI的原成员现在会继续自己的拉栓／装填，接回时保留其真实剩余弹药和动作，不因换人补满或重置。机械操作使用上述通用录音反馈，失败时明确提示并保留合成降级；短时枪口焰与抛壳表现保留，角色动画、历史音色和人工听感并未因此通过验收。

举枪用模型照门缺口与准星尖端对齐视线，射击从实际枪口向瞄准目标求交；近距离遮挡以枪口射线为准，不能只凭摄像机可见就穿墙命中。靠墙会回收、放低枪械并退出瞄具，受阻时明确提示且不能发射；移开后恢复。当前为即时射线枪械，没有重力、弹道下坠、风偏或历史归零模拟。

### 敌我AI步枪火控

两方AI共用每发合法射击的基础命中率：10米50%、20米25%、40米10%、60米3%、75米1%，中间连续线性插值，0米上限55%；受压统一乘0.55，近距离也不再保证必中。多人集火仍会危险，不把概率下降解释成玩家无敌或保证存活时间。玩家仍按实际枪口射线手动命中，没有额外命中率抽签；共同步枪射线最大180米，AI视觉／确认射界仍75米。敌我人体伤害见下节，已经不再沿用一律50的旧规则。

AI开火须实际停步（速度不超过0.1米／秒）、结束冲刺恢复、完成姿态过渡。首发仍需对同一目标连续确认射界并基本瞄准至少`0.45 + 0.65 × min(距离,75)/75`秒，受压再加0.25秒，不是一发现就瞬发。35米内同目标步枪可在0.65秒拉栓和约0.15秒复核后继续开火，轻机枪保留三发短点射。35–75米不禁射，但首发之后每发需连续稳定瞄准6–10秒，按距离插值，受压再加0.5秒；远距轻机枪也不连续点射。换目标不能绕过已产生的远距后续长瞄；靠近后恢复近距节奏。35米、6–10秒是本项目体验参数，不是历史实测或原作内部规则。

每次约0.1模拟秒复核视线／枪口遮挡及友军挡线，视觉确认断档超过0.2秒、失去射界、走动或换目标会重新瞄准，不从实时隐藏坐标补充记忆。双方使用本人的步枪／轻机枪弹仓，真实扣弹、按各自周期拉栓／循环与空仓装填；攻击敌方集结点也不能绕开。玩家手动180米射程、部位伤害和原命中概率曲线不改。

AI仍先按上述概率判断有效射击，再从真实枪口向已观察点求人体交点，并复查环境遮挡；不是已完成的真实散布弹道，未命中抽签的弹线仍可能指向目标。第三人称完整拉栓／装填动画和有限备弹也未完成。`node --test test\ai-rifle.test.js test\combat-targets.test.js test\weapon-simulation.test.js`覆盖规则，`ARTIFACT_DIR`指定目录后运行`node scripts\ai-rifle-smoke.mjs`记录实际开火、装填和暂停；新版一枪失能改变交火／装填样本的出现频率，不用复用旧生存率结论。

### 干涸河床与自然树木

`test\ground.test.js`、`test\dry-river.test.js`和`test\woodland.test.js`覆盖高度、岸坡、渲染与落脚一致性、双向通行、正常冲刺、沉积纹理双向变化、装饰放置、树种轮廓、树龄差异及根部埋入和染土过渡。开发服务器下运行`npm.cmd run test:river`，分别用普通步兵键鼠及真实坦克正／倒车在桥外双向通过河床；保留开发诊断参数`benchmark=ford`，生产构建忽略诊断参数。`npm.cmd run test:scenery`用正式场景生成器和本地材质分别拍摄干河床、近处树木及根部接地特写，另以地图中实际生成的模型制作三树型并排预览，并检查材质错误与静态合批；这是独立美术／几何检查，不是正式交火性能验收。`GAME_URL`／`ARTIFACT_DIR`用法同上。

### 实体门与F交互

首批11栋商铺的前/后门、隔间和两扇院门共35扇实体门，部分初始关闭。步兵接近并看向门口，提示出现后按F开关；门朝远离操作方的一侧打开，不瞬间消失。转动门板使用旋转碰撞，射击和视线检查实际门板；门后有人时停止，移开后继续，不通过推人或穿模完成开门。门轴提示为独立合成声音，正式拟音与整体混音仍待F11。

AI可规划通过门口，但必须实际开门并等待通过；已开启门板的占地会局部刷新到导航，避免每次开门重建全图。F/X交互在鼠标刚移动时使用最新朝向，而不是上一帧摄像机。`npm.cmd run test:doors` 检查F提示、闭门弹着、暂停、通过、受阻、内外侧开启、重开复位及通过窗户命令AI进入关闭房间的实际行为。

G1另补充了接近全开角度仍受阻时的AI主动让门：仅沿安全路径有限移动，不把人传送出去或让门板穿人。0.75米A*网格边的胶囊净空预计算并在门状态更新时局部失效，查询时复用堆、减少路径平滑重复检查；仍保留薄墙、门角和每个实际路径段的净空约束。

门板损毁、锁门/堵塞和高密度堵门仍未完成；外围旧封闭建筑没有全部改造。F采用情境优先级：车内执行地面离车，地面看向门时开关门，无门目标时可返回附近原车；同次按键只执行一个动作。飞机离机仍明确提示未实现，不能把基础坦克下车算作F10全部完成。

### G2实体归属、地面上下车与阵亡过渡

`src\entities.js`为单位、士兵、武器、载具和座位提供稳定ID。士兵持有位置/朝向、生命和个人步枪，坦克/飞机持有自身位置/车体状态、座位和主武器；当前控制器只选择所属单位和士兵ID。原`unit`接口是派生兼容视图，场景模型跟随模拟位置，不再用模型位置作为地面士兵/载具的唯一状态。不是全量ECS或完整渲染/模拟分离，角色局部动画、部分弹道/表现和UI仍有后续工作。

`src\vehicle-renderer.js`按载具ID管理坦克/飞机视图，从实体位置、车体朝向/俯仰/侧倾及炮塔角单向投影；载具模拟不再持有或直接变换模型，网格仅标记`vehicleId`供几何查询回查。每次模拟载具移动后同步实际射线几何，残骸保留到登记实体退休，重开/退出移除视图但不销毁共享资源。坐车人员、当前受控身体和地面尸体的显隐也由士兵渲染器从实体状态派生，不以旧`model.visible`反推控制或生命；没有新增正式车体、美术破坏或骨骼动画。

坦克中按F可从安全出口下车，原车不消失，原士兵恢复独立步枪；近距离看向原车再按F返回空席。检查墙、车体、其他车辆及人员，全部受阻则不改变座位/位置。当前只允许原车组返回原车，未实现接管其他单位车辆、全车组撤离指令、空中离机/跳伞、装甲车和野战炮席位。完好遗留车继续计入载具上限，不能反复下车刷车。

Y选择本车组存活成员，可以从地面成员接管仍在车内的成员，反之亦然；个人步枪、车载主炮和机枪各自保留弹药／动作，车体生命不刷新、冷却不缩短。车长／炮手可操作主炮和Space并列机枪，驾驶员只能观察／驾驶，不能以空格或鼠标越权开火；机枪和车体／炮塔方向图已接入。车长／炮手／驾驶员中立镜位眼高约为车体基面上2.03／2.03／1.3米；车长与炮手共用位于机枪正上方的观察参考点，均随炮塔转向和炮架俯仰，仍分别保留狭缝／炮瞄视野和倍率。机枪口在观察坐标中低于视线0.265米，火光与弹道仍来自未移动的实体枪口，不在观察孔右侧凭空生成；这些镜位是游戏调校，不是历史观察窗测绘。专职机枪手、AP/HE和完整驾驶权限／视野仍待F12/F26，不能称为完整坦克模拟。

我方维克斯主炮每次射击后立即自动装填，耗时3.8秒，无需按R或再次扣扳机。准星右侧圆环与倒计时读取同一模拟装填时钟；驾驶员也能看到本车进度，下车后隐藏，返回或Y换座不重置，暂停时冻结，完成后隐藏并恢复一发待射。R不启动或重置坦克装填，步兵／迫击炮等原有操作不变。装填不再套用手持武器的低头摆动，炮管保持瞄准，只保留原有射击瞬间后坐反馈。

这表示车组自动执行装填，不意味着二战维克斯具有机械自动装弹机。发射与开始装填沿用统一`shotState`，补弹由原武器实体的模拟时钟推进，不另设当前控制器私有倒计时。
`src\control-transition.js`在确认阵亡后进入独立`transferring`状态，显示暗红/阵亡提示，约0.6秒在全暗遮罩下重新选择本单位存活成员，约0.9秒恢复操作；均为本项目调试值。过渡清理输入，Y和长按射击不能提前操作新成员，战场/AI/载具/炮弹继续；Esc暂停冻结时钟，重开/回大厅清理，不采用跨局定时回调。接管后不补血、补弹或继承旧死亡红边；关闭红色效果不改变接管时间。无存活成员进入原覆灭部署。倒地救援、完整死亡动作和所有连续伤亡边界仍需专项验收。

`npm.cmd run test:control`要求开发服务器，使用显式 `?benchmark=control&seed=1938` 小样例（两组自主友军、一辆坦克三人及敌军），以普通输入验证身份/资源、上下车、驾驶员主炮限制及真实自方炮弹爆炸触发的死亡—暂停—接管链路，不使用伤害/传送/无敌接口。设置`ARTIFACT_DIR`可保存实际操作JSON和截图。发布版忽略诊断参数，默认仍为正常110／96编制。

控制诊断的坦克登记点位于`(10, 83)`，用现有东侧商铺真实遮蔽下车出口，避免长操作流程依赖暴露成员偶然幸存；敌军人数、伤害、正常AI和自主友军保留。它不是交火性能或敌军无法伤害下车人员的证据，正式重生点未改变。

当前控制链另由 `src\control-input.js` 绑定单位/士兵/载具/席位/武器ID和版本，离散命令同步执行，不额外等待一帧；旧版本或重复命令明确拒绝。Y/F改变控制对象、死亡、暂停和重开会清空按住的移动/鼠标/命令计时，**换人后需重新按下移动、举枪或开火**，避免原成员的持续输入误操作下一成员。车组下车后的个人守位使用安全出口本身，不重复叠班组偏移进入车体。

控制绑定区分实际成员/席位/武器变化与同一控制者暂停后恢复：真正交接时先在模拟侧收起工具、清理当前控制者的跳跃瞬态和未完成建造，再同步新成员个人步枪的兼容装填时钟，随后才通知模型/HUD刷新。相同控制者恢复仍让旧输入失效，但不重置其已选工具和冻结中的跳跃；建造蓝图仍按原暂停策略取消。界面刷新只读实际工具选择，不再用换模型来决定装备、跳跃或步枪弹药/装填状态。

`syncControlledRifleTiming()`不推进动作、不补弹，只同步当前个人步枪剩余装填时间；车载/班组武器仍保留自己的时钟。只读`controlBinding`记录最近一次绑定在表现消费前的状态，`controlSimulation`公开当前控制瞬态及士兵跳跃／翻越／架枪状态，不提供关闭反馈或修改游戏的测试接口。普通输入覆盖锤子状态下Y、跳跃中F入座、空中暂停恢复和返回正在装填的成员；跳跃现已改变士兵实际位置，仍不是专业第三人称跳跃骨骼动画或通用刚体物理。

AI普通步枪交火的枪口由士兵位置、朝向与阵营的既有局部偏移计算，不再读取角色模型矩阵或缩放；保持原1.39米站姿发射高度、友/敌不同枪口长度、遮挡检查、射击间隔与伤害参数。移动只更新位置、朝向和按实际位移推进的步态相位，渲染器读取该状态设置原有腿部摆动；初次移动前保持中立腿姿，停步/尸体保留既有相位表现，不额外推进模拟时间。

显示与玩家射线目标共用`syncSoldierModelPose()`单向投影：查询实际人物几何前也从当前模拟姿态同步，不隐含依赖上一帧已经绘制。规则用例比较两队不同朝向/桥面高度与原矩阵结果，并验证没有模型也能计算AI枪口、近/远LOD一致、投影不改生命/位置/步态及未渲染时实际网格可命中。第一人称枪口与射线仍使用几何适配；本项不是骨骼瞄准、真实第三人称跑姿或完整蹲卧命中区。

AI的战术位置输入现在只取最近一次观察的副本，不再因仍持有目标引用，就每步读取其真实位置来选掩体、侧移或转向。视觉记录目标身份/类别及已见位置，保留5秒；声音只记录带原有误差的声源位置，保留3秒，不借用实时目标身份。当前目标准备开火时仍需真实视线复核，成功后才刷新观察并对准实际可见位置；失败不刷新位置或延长记忆。复核后再次检查武器适用性，避免人员刚入座封闭装甲时沿用旧人员分类。

记忆过期在每个活着的AI更新中执行，不再等待有限感知预算；过期同时释放对应掩体占用、清掉旧目标和排队/已算路径，随后按命令或新观察行动。允许AI短时朝旧观察点搜索，不是失去视线就立刻忘记，也不保证看到一次后始终追踪当前位置。`test:perception`在正常规模战局用原坦克、普通W/A/D驾驶完成发现、真实几何遮挡、遮挡后继续移动与重新发现；使用已有封闭装甲规则，不改生命或传送。只读观察时间、类别、身份、实际战术点及已有视线查询结果用于核查，没有增加额外透视查询或可写测试接口。该观察边界项没有顺带实现防空武器；F32普通步枪止错及未完成部分见下文。

F32后续已补普通步枪对飞机的适用性止错：步枪AI在目标排序截取前排除飞机，不挤掉可交战地面目标，也不取消对封闭装甲的警戒。实际人员/机体伤害入口共同阻止步枪对飞机及座内飞行员扣血；手动对空射击仍正常消耗弹药并产生物理接触表现，但不算有效伤害。普通步枪对地面人员的伤害不变，已有机炮、主炮、爆炸及飞行事故仍沿用各自原型规则，不把飞机设为全局无敌。

`npm.cmd run test:aircraft-rifle`使用正常规模战场的原飞机和普通操纵，验证进入敌军候选范围后不被步枪锁定/扣血，机体及座内飞行员生命保持、随后真实坠毁和正常地面交火仍有效；规则/实际网格用例另验真实机体射线命中与离席类别变化。专用高射机枪尚未实现，其他武器对空适用性的完整设计、敌方自主飞机和飞机F离机仍待各自专项，不将本批止错称为完整防空系统。

友军接敌移动首批：已选择真实可达掩体后，接近与射击探身分开，较长的进掩体路段及受压制回撤可使用个人负重对应的冲刺速度，不再统一以1.8米/秒慢移。实际冲刺位移才消耗体力，复用玩家的消耗/延迟恢复与疲劳规则；体力不足降为慢跑，Y不补满。移动中保持行进朝向，不一边奔跑一边始终面向敌人射击；友军须停稳且冲刺后的举枪恢复结束才允许实际步枪发射。整个受压制窗口优先回到遮蔽点，不因进掩体超过1.4秒就提前探身。

仍有保护的掩体不会仅因当前探身射界暂时丢失就被重新选择；短暂承诺已选路线，受伤可提前重评，新路线也清掉旧排队路径，避免旧路径覆盖新目标。使用原实体生命、真实墙门碰撞、导航与有限感知，不提高生命、忽略遮挡或瞬移。`npm.cmd run test:friendly-tactics`在正常编制（当前110／96）通过普通W前进后观察实际冲刺/体力、至少两人贴近掩体、受压制回撤和真实停稳射击；只读`friendlyPositions`保存实际移动及最近一次开火快照，不提供可写游戏接口。此前100对100通过记录保留为历史批次。

这只是进掩体/回撤/射击切换的改进，**不是完整分组掩护跃进**。协同试验未在正常实战可靠完成，因此未保留未验证的协同逻辑；掩体链、谁掩护谁及伤亡/命令中断仍待M4。第三人称仍为原程序腿摆，不是正式跑姿；敌军主动反夺点与胜负规则也未在本项改变。

门的物理/交互回归使用开发参数`?benchmark=interior&seed=1938`：原地图与正常生命、5名友军及真实队友AI，登记在原南侧位置，无敌军或自主友军交通。该场景避免把“玩家走到门前之前没人开过门”当作正常战场保证，仍验证闭门弹击、扫掠阻挡、暂停及队友接到室内命令后自行开门；不算交火/人口性能证据。发布版忽略该参数，仍为正常110／96编制。

蹲卧选择与个人观察俯仰现在属于各士兵，通过 `createControlPoseView()`读取；Y使用新成员自己的选择，返回原成员恢复其原值，不再把上一人的低头/趴伏直接带给下一人。相机接管即取对应眼高，继续使用当前桥面/坡面支撑。地面观察俯仰与原车炮塔的原型瞄准角分开，上车不会把步枪的低头角覆盖给主炮，Y/F/阵亡接管均读取原车状态；飞机俯仰/航向属于飞机实体，保留既有限幅。成功入座仍按原规则结束个人蹲卧，离车为站姿；失败入座不改原姿态。刷新视角不再写回这些角度或姿态。

该控制批次只完成状态归属，不包含后来独立接入的人物蹲卧／命中区及坦克闭舱观察；当前车长／炮手已有不同视野与倍率，但仍共享本车主炮状态，完整四岗位装置与成品动作继续保留在F12/F14。交接清理后坐力、架枪与当前视角兼容跳跃偏移，原士兵实际跳跃／翻越继续到落地；实际入座则结束个人腾空动作。`test:bridge`覆盖站/蹲/卧跨成员恢复及桥面眼高，可用`ARTIFACT_DIR`保存实际状态记录；`test:control`同时检查地面观察角不污染原车瞄准角和死亡接管。

驾驶员观察独立存于原车驾驶席，随车体转向；鼠标不会转动炮塔或改变主炮俯仰。驾驶员不能左键发炮或用R启动装填，右键不进入炮手放大瞄准，隐藏主炮准星并显示岗位限制；Y／F保留本席状态。当前已有原型闭舱窄视窗及有界观察，具体虚拟限角见上文，不是已核实的历史设备测绘或参考车型复刻。

武器视图可见性按控制阶段及席位统一判断：阵亡移交期间新成员的武器也保持隐藏，到可操作时才显示；若连续伤亡后只剩驾驶员，接管完成也不会误显示主炮。`test:control`以实际两次近距炮击覆盖车长、炮手相继阵亡与驾驶员接管，以及驾驶观察/转向/装填限制，不使用伤害或传送写接口。

`src\control-events.js`将换人、上下车、死亡阶段、装填提示、工具视图、建造通知及本地脚步/门声反馈经有限、一次性事件交给表现层，不在下一局回放旧事件；命令轨迹32条、反馈历史64条，窗口仅公开只读快照，不提供重放/伤害写接口。语音、世界对象装配等仍有后续工作，不宣称已整体重构。`test:control`同时检查按住左键/W再Y切到车内时，坦克不自动行驶或空炮装填，原士兵和主炮资源不刷新。

`src\weapon-simulation.js`按实体推进武器动作，不再在人物移动/镜头更新里推进拉栓，也不对当前载具重复更新装填。当前有效控制者的步枪只在装备时推进，收起／入座暂停；主游戏显式开启AI个人武器时钟，其他存活且未入座的士兵继续本人的拉栓／装填，AI空仓会自动排队装填。Y只转交控制，不重置任何武器；AI装填可在接管前自然完成，但不能被当成Y免费补弹。已启动的车载／班组支援武器装填仍独立完成，空支援武器不自动启动装填；全局暂停不推进任何武器。

机械动作只产生带士兵/武器ID的一次性反馈事件，由当前有效视角消费；其他AI或已收起步枪的声音不能串入新视角。换队时注销原单位支援武器登记，不让反复迫击炮出击积累无主武器，也不改写其已发射炮弹的原始来源。规则覆盖100次替换及30/60/144Hz；新增AI策略明确检查双方时钟、空仓装填、Y连续归属及阵亡／入座／全局暂停。有限备弹、AI空间机械音和第三人称装填动作仍未完成，相关G4/F11不因此勾选。

`src\construction.js`独立管理玩家工兵的蓝图归属、锁定位置、进度、取消及一次性完成结果，不读取相机、模型或DOM。候选点由士兵模拟朝向与共享地面高度计算，仍为前方5米；每步复用原位置/敌情/据点校验，保留6秒建造门槛及移动超过0.7米清进度、继续按住时在新候选位置重新起算的规则。蓝图绑定具体建造者，Y、收起工具、暂停、死亡和重开按原策略取消未完成任务，不让新队员继承进度；暂停不保留半成品供恢复后补齐。

HUD、预览颜色/位置只读取建造状态，完成/位置变化提示通过有限反馈事件消费。集结点登记保留原建造者ID，创建时核查其仍是本队活着的工兵；已建成集结点不因建造者换人或阵亡自动消失，仍受原耐久、损毁、敌情封锁和重部署规则控制。`test:browser`记录松手、Y、暂停取消以及正常完成/摧毁/部署，规则另验30/60/144Hz、位置锁定和单次完成。

集结点创建/替换/耐久转移由 `src\spawns.js` 的纯状态函数处理，每阵营仍最多一个，初始耐久120。重生点不再持有模型，`src\rally-renderer.js`按ID维护实际显示及射线目标；网格只标注`rallyId`，命中后回查登记状态，不把整个重生点对象塞进网格。损毁立即让部署校验失败，世界通知在表现层刷新提示/部署面板；重复命中已毁目标不重复触发损毁。替换、损毁、回大厅/重开清理旧显示和射线目标，不逐点销毁共享几何/材质。

规则与实际网格射线用例覆盖同阵营替换、两队隔离、已毁状态、渲染前即损毁及重开；`test:browser`检查普通步枪实际命中登记ID、耐久归零、对应视图移除和新局清理，`ARTIFACT_DIR`保留记录。当前弹道仍通过现有Three.js几何适配器求交，未改成独立物理引擎，也未增加集结点对地面移动/导航的阻挡规则。

迫击炮在飞弹由 `src\projectiles.js` 拥有起点、目标、当前位置、飞行时间和伤害，渲染网格只跟随模拟，不再由网格位置反推弹道。发射时冻结原单位/士兵/武器/载具/席位及个人或友军击倒归属；步枪、主炮、机炮和AI步枪的伤害也记录实际武器来源。换人、阵亡、撤出旧实体登记或同局重新部署不会改写已经发射的炮弹，暂停冻结其模拟；返回大厅或新局清理弹体、渲染对象及旧弹着记录。碰撞使用实际场景与载具几何，每弹只结算一次；在飞上限32、弹着历史32条，共享弹体几何和材质不逐弹销毁。

### 冷灰日光、枪口与基础弹着

### 可选步枪PBR资源接口

`src\weapon-assets.js` 的 `RIFLE_PBR_ASSETS.wood/steel` 可配置本地 `public\assets` 下的贴图，浏览器路径采用 `/assets/...`。默认各通道为 `null`，保留程序化材质，不自动下载或要求外部服务。配置前应人工核对资源适用性与CC0许可证，并在对应项记录 `license: 'CC0-1.0'` 与 `source` 原始来源；配置声明本身不能代替授权审查。

可用通道为 `color`、`normal`、`roughness`、`metalness`：颜色使用sRGB，其他为线性数据；法线要求 `normalFormat: 'OpenGL'`，粗糙度读G、金属度读B，灰度图可直接使用。木托不允许配置金属度贴图；配置新木色时清除旧生成纹理的bump，避免错配。钢部件共享资源，前后视角仍使用同一枪体/材质。没有实现glTF模型替换或自动资源制作。

路径只接受本地 `/assets/`，非CC0声明、未知字段、错误法线方向或文件缺失会显示具体错误并阻止不完整资源出击，不静默回退。`npm.cmd run test:rifle-textures` 使用原始自制测试贴图检查真实加载、颜色空间、共用请求及失败提示；它不证明已制作出写实枪械表面。

### 普通步枪与封闭装甲：有限止错

敌军步枪兵识别封闭坦克后不再持续无效开枪，也不能靠普通步枪命中直接扣整车生命；会先寻找掩护、近距避让或保持警戒。伤害入口按人员当前座位归属检查武器/目标类别，下车成员恢复人员目标，不会因为玩家切回车内就让所有地面车组免疫轻武器。爆炸和当前其他武器保留原型伤害，**不是完整装甲穿深或已经拥有反坦克装备**。

本轮未新增火箭筒、反坦克手雷或炸药包，F13整体仍未完成。另修复同一次爆炸在自动切换受损车组后重复伤害同一车体的问题。`npm.cmd run test:armor` 通过正常坦克出击/接敌确认没有步枪火力和车体扣血，再用实际爆炸核对坦克仍可受损，并重新以步兵出击核对普通交战不受影响。

### 重生与工兵：当前明确规则

这些是为约220米宽的小地图采用的**原型参数，不是《Enlisted》的原始数值**：

- 中国步兵、迫击炮组从南侧步兵集结地或工兵集结点出击；坦克从装甲出发点出击。飞机从固定的南侧空中入场点进入，尚无机场起降。
- 日军首次部署和后续增援从北侧基地进入；日军工兵建成前线集结点后，后续增援优先使用它。重生点附近有对方地面部队时不能使用；飞机飞越不触发这一地面封锁条件。
- 每方最多保留一个工兵集结点，新建会替换旧点；建造耗时6秒、耐久120，敌军在18米内阻止建造与重生。建造点须在未占领据点边缘18米以外，周围留出2.8米生成空间。地形受阻会明确显示原因。
- 开局步兵一班的第一名队员为工兵。按2取出工具，右键启用集结点蓝图，绿色可建、红色不可建；按住左键完成建造，松手或明显移动会中止。当前不保留未完成蓝图，也没有工程材料消耗。
- 集结点可被双方枪炮破坏；敌方AI会射击发现的我方集结点。摧毁后提示、地图标记和部署可用性同步更新。己方集结点跨小队阵亡保留，新一局才清空。
- 五个独立班组是小队身份，不是五个兵种：步兵一班、步兵二班、迫击炮组、装甲车组、航空小队。换人不等于换队；步兵一班覆灭后，步兵二班仍是另一个合法选项。
- 当前禁止立即重选刚阵亡的班组，并有每方最多2个载具单位的限制；自主步兵整队补充使用17秒冷却，敌方坦克小队按独立补充规则处理。**未实现原作所有模式的小队轮换／冷却、多人重生排队或完整工兵个人建造上限**。单人原型不伪造其他真人玩家的排队。

### 连续操作稳定性与错误诊断

开发服务下运行`npm.cmd run test:stability`，默认`GAME_URL=http://127.0.0.1:5213/`；需先启动同端口开发服务，`ARTIFACT_DIR`可保存观测JSON与画面。顺序执行两轮不刷新页面的“靠墙举枪→蹲／卧／起身→转身恢复→射击拉栓→蹲姿换弹中暂停／恢复→再射击→大刀挥砍→选雷／收起→按住移动与瞄准时Y换人→循环切回→返回大厅／重开”，检查模拟推进、手臂恢复、个人弹药／投掷物库存、旧输入清理与重开实体清理。随后复用掩体／翻越／轻机枪换弹及真实爆炸死亡接管脚本，最后验证错误界面。各场景之间明确重开，不宣称在同一战局覆盖所有兵种；这些使用标注的小规模几何／控制诊断，不代表正式人口长局、性能达标或视觉验收。

错误界面区分加载失败、运行中断和WebGL上下文丢失；初始化与未处理Promise失败也保留首个原因，不被后续重抛覆盖。不可恢复错误会停止模拟并阻止后续游戏输入，不假装恢复成功。可复制本页实际构建提交／是否含未提交改动／构建时间、错误堆栈、阶段和最小控制／武器上下文；不自动上传，不含账号、完整场景或存档。剪贴板被拒绝时明确提示，并选中只读文本供Ctrl+C手动复制。`test\fatal-report.test.js`与`scripts\fatal-report-smoke.mjs`覆盖真实资源失败、运行时异常、Promise拒绝、显卡上下文丢失及复制失败；加载脚本自身未能执行等页面外部故障不在此模块覆盖范围。

独立验证生产错误界面时，先启动生产构建的preview，将`GAME_URL`指向该服务并设置`GAME_PRODUCTION=1`，再运行`node scripts\fatal-report-smoke.mjs`；此模式不启用开发诊断人口，并检查报告确实标为生产构建。不要把此变量带入仅面向开发诊断的整套`test:stability`。

### 活跃战局时钟与长帧追赶

`src\simulation-clock.js`替换原来每帧截断至50毫秒并丢弃余量的做法。正常帧保持实际帧间隔；长帧拆为每步最多50毫秒、每次绘制最多5步。**恢复帧另以本帧真实活跃间隔的1.1倍限制推进预算**，不再因为有积压就连续每帧推进250毫秒，造成玩家、AI和全战场突然快放。未处理时间继续保留、缓慢追赶，不丢弃事件或重置计时；相应代价是积压恢复需要更久。门、载具、武器、人员、AI、据点、炮弹和死亡接管使用同一批子步；每步消费反馈，画面最终绘制一次。积压达到0.25秒时HUD明确提示余量和追赶上限，开发逐帧记录包含补步数、积压和活跃总时长，不通过减兵或隐藏落后取得“正常”计时。

暂停结算其前的活跃边界并保留积压，不计入暂停期间墙钟，也不在暂停中推进；恢复后使用原控制归属并清旧按住输入。同局覆灭/重部署不重置战场时钟，回大厅或开新局显式清理旧时钟。短寿命世界枪口光、弹道线和爆炸以本批最终显示时刻出生，避免在首次绘制前被后续补步耗尽；伤害/击倒来源和事件时间仍为真实模拟时刻，个人红边与命中标记仍按原模拟规则。

`npm.cmd run test:clock`使用明确标注的无敌军桥面诊断，通过普通输入射击和650毫秒主线程阻塞验证5步上限、积压提示、随后追回完整时间、枪口光首次可见、保留未处理积压的暂停/恢复及跨局清理；没有更改生命/位置或提供可写测试接口。`node scripts\movement-speed-smoke.mjs`另在正常战场通过真实输入和前台阻塞检查追赶预算及实际位移，不仅断言标称跑速。该诊断不算持续200人性能证据。当前是有界可变子步，不是完整固定tick/渲染插值或历史输入回放；严重持续过载仍可能累积落后，短暂个人反馈也仍需低帧率人工复验，不能把不丢时间说成已消除长帧或达到稳定60FPS。

浏览器冒烟检查默认通过本机已安装的 Google Chrome 无头运行，需要先启动开发服务器；可用 `GAME_URL` 指定地址、`ARTIFACT_DIR` 指定截图目录。它检查工兵工具、建造中断/完成/摧毁、重生来源、敌军工兵前线点及增援、射击和小队操作、阵亡后选择与确认、选择期间战斗继续、载具及重新开局；不评估美术质量或历史准确性。
